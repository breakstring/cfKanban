# cfKanban local MCP

This package builds the shared local stdio adapter and internal Host facade. The repository root lockfile fixes its SDK and build dependencies. Run the root build, or `npm run build --workspace @cfkanban/mcp` after `npm ci`.

The build reads the fixed version from `release/version.json` and emits the server, facade, `search-cache-worker.mjs`, fixed workbench document, build metadata and dependency notices. JavaScript entries include their runtime dependencies; installed artifacts need Node.js >=22.12.0 and no package download or compilation at launch. The SQLite Worker uses Node's built-in driver; compatibility flags apply only to that Worker. Releases copy and verify the complete fixed file set in `mcp/`.

Composer search supplies the standard MCP display title `cfkanban-search` while retaining the stable server name `cfkanban-mcp`, and matches identifiers, number prefixes and title fragments in a private persistent SQLite cache. Candidate reads make no HTTP request; selected resources still use live Service authorization. Startup and active-search background synchronization refresh the cache, including complete snapshots for newly authorized Projects. Cached titles may temporarily outlive revocation until synchronization confirms it. The cache stores no Credential, body, Comment or ACL and is isolated by instance, Principal and trusted origin binding.

Hosts start the installed `mcp/server.mjs` with a verified absolute Node executable and an argument array. The server takes no arguments or state-path overrides. It reads private state from the actual execution user's home for each operation. Its stdout carries MCP protocol messages only; stderr diagnostics contain fixed, non-sensitive text.

Native Host integrations import `createMcpFacade` from the installed `mcp/facade.mjs`. `listTools()` supplies the exact strict schemas; `callTool(name, arguments, { signal })` returns the Service result or a safe local refusal. Internal bindings fix instance, Principal, and Project IDs. An identity-only binding with empty Project IDs permits connection inspection, Workspace/Project discovery, and saving only that Principal's locale. Tool arguments cannot change a binding or access arbitrary URLs, files, credentials, administration, deployment, or Browser Launch delivery.

Skills prefer the current host's connected MCP for daily operations covered by its discovered schema. The current catalog has 26 tools, including Project and Workspace Issue trends, Project milestones, optional Issue membership, self locale preferences, bounded Project label lists, and single Issue label add/remove; scripts retain uncovered semantics and lifecycle/sensitive delivery flows, and remain available to hosts without MCP. Tool discovery and connection inspection do not require preliminary script `help`, environment probes, or directory inspection. Directory recommendations still use the safe scope scripts when relevant. Callers must not invent tool names, approximate unsupported operations, or start another server to bypass host restrictions.

Each write requires one stable key and the applicable CAS versions. A timeout, cancellation, or response loss can leave `outcome_unknown`; retain `recovery_request`, the original caller/tool/arguments/key and request IDs, then read back before deciding whether to replay the identical request through that caller. Permission refusals, CAS conflicts and unknown outcomes never trigger a cross-channel script retry or a replacement write. Restore the original connection as needed to inspect or recover the retained operation; reconnection is not evidence of non-commit. Choose a new execution path only with evidence that no request was sent. There is no automatic retry, completion, or write orchestration. Repository Project scope is not read by this first adapter; callers supply explicit Project IDs, or explicitly acknowledge an authorized aggregate read.
