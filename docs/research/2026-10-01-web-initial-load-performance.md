# Web 首次加载性能基线（2026-10-01，CFK-535）

本次对比使用本地生产构建和合成 API，未部署、未测量线上实例。源码基点为 `e053e90c62dede0056be86cbb723ec6d7377c581` 的 `feat/v1.5.0` 工作区；三次采样对比的优化前构建已包含 CFK-531～534，优化后只增加 CFK-535。用户随后要求将语言入口改为通用图标、移除业务弹窗里的重复入口；最终构建及其定向复核单独列在下文，不与三次采样混用。发行说明中的 v1.5.0-rc.1 数值是历史数据，不代替本次基线。

## 构建归因与实现

原入口静态导入全部 11 个 View，产物为一个 875,732 B JavaScript 文件，gzip 258,757 B。页面包含 Owner 管理、详情及参与者功能；不存在可归因的大型第三方 Markdown/高亮库。优化后保留 Vue/Vite 与同 Worker assets 架构，业务页动态导入，Nuxt UI provider 和认证页头也仅在认证路径加载。成功加载只缓存组件模块，不缓存身份或业务数据。

会话核验后并行预加载当前页与页头，预加载不挂载组件、不发送业务请求；Owner 页面继续检查 Owner control-plane 能力。加载失败保留到显式重试，离页后旧 Promise 不挂载页面。刷新最新版本只能由用户点击，沿用草稿 `beforeunload` 保护。

共享分组先固定入口静态依赖，再独立保留首页共用的四个轻量工具；其余共享依赖按实际入口集合合并小组。模块图核对确认 bootstrap 没有任何 View，首页仅包含 PublicHomeView，没有 Owner、看板或详情代码；静态 chunk 图无循环。没有提高 Vite 大包告警阈值或升级依赖。

| 三次采样对应的构建指标 | 优化前 | 优化后 |
| --- | ---: | ---: |
| 入口 / 最大 JS raw | 875,732 B | 238,918 B |
| 入口 / 最大 JS gzip | 258,757 B | 85,805 B |
| 全部 JS raw（包含未首屏加载页面） | 875,732 B | 899,657 B |
| 全部 JS gzip（各 chunk 单独压缩后相加） | 258,757 B | 290,195 B |

按需加载减少当前页面所需代码，但 chunk 包装、引用与压缩边界增加全部页面累积体积。入口体积不能代替首屏全部 JavaScript；浏览器对比需包含实际加载的同步和动态依赖。

## 同条件浏览器测量

- macOS、Node v24.19.0、Chrome 154.0.8037.58，headless，1440 × 1050。
- 同一 localhost origin，静态文件使用 Node `gzipSync` 默认压缩；使用真实生产 assets，API 返回合成 fixture，不读取凭据或访问线上。
- CDP 冷缓存：禁用缓存、150 ms latency、上下行 160 KiB/s、CPU 4×。每个场景独立上下文，三次采样取中位数，采样期间不并行构建或测试。
- 可交互终点：目标页 ready marker 出现后，真实点击语言入口，将 HTML `lang` 改为 `zh-CN`。该值是明确交互终点，不冒充标准 TTI。
- 首次导航使用真实 Public Join mock、卡片打开、账户菜单进入管理。导航列报告增量 JS；首次进入和后续共享依赖复用必须分别观察。
- `ScriptDuration` 与 `TaskDuration` 是 CDP 执行/任务指标，不等于纯解析时间。另采单次 tracing 观察 Chrome 实际 compile/evaluate 事件，不能将嵌套事件相加或将 tracing 的额外开销代入中位数。
- localhost HTTP/1.1 与线上 Cloudflare 多路复用、真实 API 延迟及边缘压缩不同；本次对比不包含 Worker 冷启动或真实 D1 查询成本。

## 最终语言入口修订的复核

最终构建将全局语言按钮改为内联通用翻译图标，保留当前语言和目标语言的 `title` / `aria-label`，点击区域为 44px；业务弹窗不再重复提供语言入口。入口为 `assets/index-dgHHqKQt.js`，raw 238,854 B、gzip 85,891 B；同步闭包与最大 chunk 均为 gzip 85,891 B。仍为 24 个 JS 文件，全部 JS raw 899,536 B、各 chunk gzip 合计 290,291 B。

同样的冷缓存、网络与 CPU 节流条件下，各补采一次首页和看板：可交互分别为 1,503.8 ms / 3,073.8 ms，全部首屏 JS gzip 为 92,649 B / 193,435 B，请求数为 3 / 13。它们是最终 UI 修订后的单次检查，不能代替上文三次采样中位数。原始记录为 `after535-icon-quick-performance.json`，无浏览器错误或网络失败。

最终生产构建通过五项定向浏览器检查：图标的无障碍名称、提示与键盘操作，320px 公开和认证页无横向溢出，新建与完成弹窗没有语言按钮，关闭弹窗后通过全局页头切换语言再打开仍保留草稿，详情编辑草稿在页头切换语言后保留。记录为 `after535-icon-ui-result.json`。本地 Service ZIP 的全部 250 个 Web 文件与当前 dist、浏览器验收的冻结 dist 逐字节一致，41 个 manifest 资源、24 个 JS chunk、缓存头、Worker 与文档均完整；验证 ZIP 仅用于本地检查，没有发布或部署。

## 预算与重新测量

构建与 Service 打包通过 [web-performance-budget.json](../../scripts/web-performance-budget.json) 和 [manifest 校验器](../../scripts/lib/web-asset-manifest.mjs) 强制以下 gzip 预算：入口 ≤90,000 B、入口同步 JS 闭包 ≤95,000 B、最大 JS chunk ≤90,000 B。预算包含共享依赖，压缩使用 Node `gzipSync` 默认参数；最终入口 85,891 B 留约 4.6% 空间，仍显著小于原 258,757 B 单包。入口拆成更多同步 chunk 时，闭包预算继续生效。

执行 `npm run build` 可复核体积、HTML 与 manifest 入口对应、所有静态/动态引用、CSS 和资源文件存在；缺 chunk、错引用或超预算会失败。Service 打包复制完整 dist 后再校验闭包；HTML 沿用 `no-store`，指纹 assets 沿用 immutable。另验证旧 HTML/旧 chunk 失效时错误提示和用户刷新读取当前 HTML 的路径，不宣称跨部署保留旧 assets。

同上述 fixture/节流条件下重新采三次：首页全部首屏 JS gzip 目标 ≤100,000 B、看板/详情/管理 ≤225,000 B；直接访问可交互中位数首页 ≤1,800 ms、业务页 ≤3,300 ms；首次导航首页→看板 ≤2,700 ms、看板→详情 ≤1,100 ms、详情→管理 ≤1,800 ms。时间预算用于同条件人工复测，不在共享 CI 以墙钟时延作硬门禁，也不外推到任意网络或线上 API 延迟。
