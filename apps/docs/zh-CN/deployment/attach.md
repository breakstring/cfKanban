# 在新电脑接入已有部署

换电脑包含两个目标：获得应用 Owner 访问，以及建立本地部署维护记录。二者分别完成，不需要重新部署或复制长期凭据。

## 先接入 Owner 身份

```text
请用 $cfkanban-admin 把这台电脑接入 <实例地址> 为同一个 Owner，设备名为“<名称>”。
```

已有 Owner 设备或受支持的管理网页批准新设备请求，再由新电脑核验。详见 [Owner 设备](../administration/devices.md)。若当前已有另一身份，需要明确选择保留旧身份后切换。全部访问丢失时先检查 [恢复路径](./recovery.md)。

添加应用设备只提供应用管理能力。它不会登录 Cloudflare，也不会创建部署维护记录。

## 建立本地维护记录

```text
请用 $cfkanban-deploy 在这台电脑接入 <实例地址> 的已有部署，方便后续维护。
核对当前 Owner、准确 Cloudflare 资源和已运行版本；只保存本地维护记录，不升级或改动远端。
```

需要当前有效 Owner API 身份、准确 Cloudflare 账户控制权限，以及正在运行版本的可验证发行工件。缺少旧本地记录时，Agent 可在已确认账户内只读发现候选；多个候选或仍有未确认项时，先选准实例。

Agent 核对 Worker、D1 绑定、实例标识、schema 和迁移记录、当前 Owner、可信入口，以及既有域名、R2 和统计设置。确认计划后，只向私有本地目录保存维护记录。预期远端资源、数据库和认证配置保持不变。

## 记录能证明什么

新记录证明本次实际观察并核对的实例状态。若缺少原部署工件的历史证据，不能因为版本号相同就宣称过去部署的是某个准确摘要；相应来源会标为观察到的远端基线。

以后升级要明确说明这项历史来源限制，仍完整验证目标发行与数据库基线。接入不能修复未知绑定、迁移漂移或部分部署，也不会偷偷补数据库记录。

**在网页中：** Owner 设备批准可在应用管理页完成。部署接入没有 Web 按钮，必须由能访问本地环境和 Cloudflare 控制面的 Agent 执行。仅持有 Passkey 不等于获得本地 API 凭据或 Cloudflare 权限。

## 常见问题

**能直接复制旧电脑整个目录吗？** 推荐通过独立设备凭据和接入流程验证目标，不把长期秘密搬入聊天、仓库、临时目录或浏览器。接入不会要求导出秘密。

**已接入，能立刻升级吗？** 接入与升级是独立操作。使用 [实例升级](./updates.md) 形成准确计划后再执行。

**后来轮换或恢复了 Owner？** 用接入流程重新核对当前身份和资源，更新维护记录；不要手改旧记录中的凭据标识。
