# 中断与恢复

部署中断或身份丢失时，先核对已有状态。不要重新初始化已有站点。

## 继续中断的部署或升级

```text
请用 $cfkanban-deploy 继续我在 <实例地址或部署目标> 中断的部署或升级。
先检查已经完成的步骤，再继续剩余工作；如果需要改变原计划，请先告诉我。
```

需要对应 Cloudflare 权限和原维护记录。Agent 会沿用原计划及记录，先核实再继续；超时不代表云端没有执行。不要为了重试改资源名称、删除本地记录或新建身份。

如果首次数据库迁移失败或结果不确定，Agent 会先读回数据库。没有完整迁移成功的证据时，会停止并说明剩余状态，保留同一计划及记录供核对，不会自动重复迁移或重建数据库。

**在网页中：** 没有部署续做按钮。能打开首页也不代表部署所有步骤都已完成。

## 选择身份恢复方式

| 当前情况 | 下一步 |
| --- | --- |
| 另一台电脑上的 Owner 身份仍可使用 | [添加 Owner 设备](../administration/devices.md) |
| 仍有可用的 Owner 管理网页 | 先让 Agent 检查能否通过网页批准新设备 |
| 普通参与者无法使用原身份 | 请 Owner 签发身份恢复邀请 |
| Owner 无法通过上述方式接入，或需要撤销全部旧设备凭据 | 使用下面的 Owner 全失恢复 |

## Owner 凭据全失恢复

```text
我的 Owner 凭据全部丢失了。
请用 $cfkanban-deploy 在我的 Cloudflare 账户中核对 <实例地址>，
说明恢复原 Owner 及撤销全部旧凭据的影响，先不要执行。
```

需要控制该站点所在的 Cloudflare 账户；仅有 Passkey 不足以执行此恢复。恢复保留原 Owner、任务、成员权限和历史，会撤销所有旧 Owner 的 Agent 凭据及由它们建立的网页登录；独立 Passkey 及其会话保留。

核对目标和影响后，可以确认：

```text
我确认执行刚才核对的 Owner 恢复计划，撤销全部旧 Owner 凭据并保留独立 Passkey。
请完成恢复并验证我仍是原来的 Owner。
```

新凭据由 Agent 安全保存在本机。此流程不会建立新 Owner 或清空数据；中断后继续原操作即可。

## 数据恢复的边界

身份恢复不是数据库恢复。技能不提供一键备份恢复；回退服务程序也不会回退数据库。覆盖数据库可能丢失新数据，必须单独核对目标和影响。
