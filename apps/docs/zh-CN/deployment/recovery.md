# 中断与恢复

先区分部署中断、应用设备接入失败和身份丢失。恢复应沿原操作核对实际状态，不重新初始化已有实例。

## 继续中断的部署或升级

```text
请用 $cfkanban-deploy 检查我中断的 <实例地址或部署目标> 操作。
读取原计划与维护记录，核对远端实际状态，并在原授权仍有效且无漂移时继续。
```

需要原本地计划、操作记录及对应 Cloudflare 权限。Agent 会核对资源归属、Worker 当前部署、数据库迁移记录和实际 schema；若 Owner 初始化曾返回不确定结果，还会先检查已提交事实。

预期结果可能是完成尚未执行的步骤、核验已经提交的步骤，或明确报告无法安全继续的具体差异。命令超时不代表云端没有执行；不要换资源名称或生成新凭据来试一次。

同一任务和未变化的完整获批计划可以继续。计划改变、任务授权不再适用或用户原本限制了执行范围时，应展示当前准确影响后重新确认。不要删除 pending 状态、维护记录或未知锁文件来绕过停止条件。

**在网页中：** cfKanban 没有部署续做按钮。网页可辅助检查站点可达性，但不能代替迁移、资源和 Owner 身份读回。

## 选择正确的身份恢复路径

| 当前情况 | 路径 |
| --- | --- |
| Owner API 凭据仍可用，想更新秘密 | [管理：普通轮换](../administration/devices.md) |
| 另一设备仍可管理，想接入新电脑 | [管理：添加 Owner 设备](../administration/devices.md) |
| 本地秘密丢失，但有有效 Owner 管理网页会话，服务端仍有未撤销 API 凭据记录 | 网页批准新设备，再到新设备验证 |
| 普通参与者丢失身份访问 | 由 Owner 签发准确参与者恢复邀请 |
| 无法走上述 Owner 接入路径，或需要撤销全部旧 Owner API 凭据 | 本页的部署外 Owner 恢复 |

## Owner 凭据全失恢复

```text
我的 Owner 凭据全部丢失了，本地记录也可能没有。
请用 $cfkanban-deploy 先检查恢复条件，在已确认的 Cloudflare 账户里定位准确实例，
展示同一 Owner 的恢复计划与全部旧 API 凭据的撤销影响，暂不执行。
```

需要准确 Cloudflare 账户下 Worker/D1 的控制权限，不依赖旧应用凭据。Agent 在已确认账户中识别 cfKanban 实例标记与公开入口；名称前缀不是身份证据。多候选或检查不完整时先选择目标，不能默认为唯一实例。

恢复计划应说明：保留同一个 Owner Principal、名称、业务内容、成员权限、指派和历史；撤销该 Owner 全部旧 API 凭据及其派生浏览器访问；保留独立 Passkey 和由它独立建立的会话。替代凭据安全保存到当前本地私有环境。

```text
我确认执行刚才核对的准确实例 Owner 恢复计划，撤销全部旧 Owner API 凭据并保留独立 Passkey。
请用 $cfkanban-deploy 执行并验证同一 Owner 的新凭据。
```

完成后应读回恢复操作并使用新凭据核验原 Owner 身份。恢复不新建 Owner、不部署 Worker、不迁移 schema，也不重建空数据库。中断时沿同一计划与替代凭据继续，不能重复签发。

**在网页中：** 专用全失恢复没有匿名或应用内恢复按钮。即使能用 Passkey 登录，专用流程仍需 Cloudflare 权限。可用的网页设备批准路径见上表，它与撤销全部旧凭据的全失恢复不同。

## 恢复不包含什么

技能不提供完整数据库导入导出、一键备份恢复或自动 D1 Time Travel。Worker 回滚不会回滚数据库。需要覆盖数据库的数据恢复属于独立高影响操作，要先明确目标与数据损失范围。
