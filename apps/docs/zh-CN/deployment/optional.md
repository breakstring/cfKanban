# 域名、附件、统计与访问限制

默认部署只包含核心 Worker、D1 与网页。可选配置应按目标分别提出计划，说明资源、费用与权限变化。

## 自定义域名

```text
请用 $cfkanban-deploy 检查为 <实例地址> 使用 <目标域名> 需要哪些 Cloudflare 和 DNS 变更。
先提出准确方案，保留现有访问能力，暂不修改。
```

需要对应 Cloudflare 资源与域名控制权限。标准首次部署使用 `workers.dev`；普通升级不会新增、删除或接管域名和路由。已验证的现有自定义域名可以在接入与后续维护中保留，但新增或迁移域名需要单独评估计划，不能承诺一句提示词就由标准升级自动完成。

**在网页中：** cfKanban 不提供 DNS 或 Worker 域名绑定编辑器。完成平台配置后，Owner 可用 [管理技能核对并修改首选 API 地址](../administration/settings.md)。两步含义不同：应用地址设置不创建 DNS，也不证明新域名已经正确绑定。

预期先得到具体变更方案与验证方法。执行后应核对 HTTPS、准确实例与新旧入口；认证请求不能靠跨域重定向传送凭据。

## 启用私有附件存储

```text
请用 $cfkanban-deploy 为 <实例地址> 准备启用 Issue 附件的升级计划。
说明私有 R2 桶、权限、订阅、可能费用和清理任务，先不要开通或部署。
```

需要支持附件的 Service、准确 Cloudflare 权限和可用 R2 条件。计划包含一个属于本实例的私有 Standard R2 桶、Worker 绑定和每小时清理。R2 订阅、潜在费用及可能扩大的 OAuth 权限要单独明确；成功登录不证明订阅或桶权限已经可用。

批准计划后，Agent 核对准确资源、创建并验证归属，再部署和读回绑定及清理配置。不会接管未知已有桶，或自动公开、清空、替换和删除桶。

**在网页中：** 没有 R2 开通按钮。部署后由 Owner 在「管理中心 → 概览 → 用量与限额 → 设置上限」明确选择应用容量，详见 [附件容量](../administration/settings.md)。未设置容量时仍不能开始新上传；部署不能替 Owner 自动选择“不限制”。

预期完成后有权限的用户可以在任务详情使用附件。单文件最多 10 MiB，每个任务最多 20 个未删除附件；应用容量不限制也不会取消这两项限制。软删除不会立即释放字节预算，项目永久删除的对象回收是异步的。

## 配置 Cloudflare 用量指标

```text
请用 $cfkanban-deploy 检查此实例的 D1/R2 用量统计配置，
提出只读 Analytics 权限和安全配置方案，不接收或输出秘密。
```

统计配置可选。没有统计凭据或设置不完整时，应用返回「未配置」，核心功能和附件应用预算仍可用。采集按需刷新，不新增统计定时任务。

Agent 可以计划准确账户、D1 和可选 R2 的非秘密配置；独立只读 Analytics Token 需通过另行授权的安全 Cloudflare 输入配置为 Worker Secret。当前部署安全工具不提供该 Secret 的写入命令，也不会上传或复用本机 Wrangler OAuth 凭据。不要把 Token 放进提示词。

**在网页中：** 「概览 → 用量与限额」显示采集状态并提供刷新。Secret 绑定存在不等于采集成功；配置后需用 Owner 刷新验证实际指标。Web 和 Agent 共享缓存，刷新不承诺实时账单数据。

## 访问频率限制

```text
请用 $cfkanban-deploy 评估此实例当前的访问频率限制。
结合 <实际流量和限流现象> 提出调整方案，先说明与项目配额的区别，不直接部署。
```

请求限制属于 Worker 部署配置。应用 Owner 可在「概览 → 服务信息与访问限制」只读查看，修改需要准确 Cloudflare 部署计划；工作区或项目管理员不能通过应用设置调整它。

预期先核对实际配置与限流来源，再决定是否变更。它与 [公开加入活跃配额](../administration/public-join.md) 不同，也不能作为精确账单封顶。不要把每个 `429` 都解释为项目人数不足或直接扩大所有限制。

## 维护已有可选配置

升级时保留已经验证的域名、R2、清理任务和统计设置。遇到未知绑定、路由、订阅或权限变化时，先说明差异。取消应用访问或停用功能不意味着底层资源已删除，也不自动撤销费用。
