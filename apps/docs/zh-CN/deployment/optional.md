# 域名、附件、统计与访问限制

这些配置可以在需要时启用。先让 Agent 说明资源、费用和权限影响，再决定是否执行。

## 自定义域名

```text
请用 $cfkanban-deploy 检查如何让 <实例地址> 使用 <目标域名>。
说明需要的域名配置、影响和验证方法，先不要修改。
```

需要相应 Cloudflare 和域名控制权限。默认站点使用 `workers.dev`；新增或迁移域名需要单独安排，不会随普通升级自动完成。

**在网页中：** cfKanban 没有域名配置入口。完成云端设置后，再让 Agent [核对站点访问地址](../administration/settings.md)。仅修改应用地址不能完成域名迁移。

## 启用附件

```text
请用 $cfkanban-deploy 为 <实例地址> 准备启用附件存储的计划。
说明 Cloudflare R2 的订阅、权限和可能费用，先不要开通或部署。
```

附件使用私有 Cloudflare R2 存储，需要额外的订阅和权限检查。确认计划并部署后，由 Owner 在网页「管理中心 → 概览 → 用量与限额 → 设置上限」选择[附件容量](../administration/settings.md)，才能开始上传。

单文件最多 10 MiB，每项任务最多 20 个有效附件；选择不限制总容量也不会取消这些限制。删除文件不会立即释放存储额度。

## 查看 Cloudflare 用量

```text
请用 $cfkanban-deploy 检查如何为此实例启用 Cloudflare 用量统计。
说明需要哪些权限、如何安全配置，先不要修改。
```

统计是可选功能，未配置时不影响任务协作。配置需要额外的只读统计授权；当前部署技能不自动写入统计密钥，需要按 Agent 说明使用安全的 Cloudflare 配置入口。不要把 Token 粘贴到聊天，也不要让 Agent 输出它。

**在网页中：**「概览 → 用量与限额」可查看状态和刷新数据。数据可能延迟，不是实时账单，也不是账户剩余额度。

## 调整访问频率限制

```text
请用 $cfkanban-deploy 检查 <实例地址> 出现请求过多的原因。
结合 <发生时间和现象> 评估是否需要调整，先不要部署。
```

Owner 可在网页「概览 → 服务信息与访问限制」查看限制；调整需要 Cloudflare 部署权限。访问频率限制与[公开项目人数及内容配额](../administration/public-join.md)不同，出现请求过多不一定是项目已满。

已有可选配置在升级时应保留。停用应用功能不会自动删除云资源或停止收费。
