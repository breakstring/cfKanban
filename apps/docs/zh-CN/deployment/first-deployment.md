# 首次部署

使用正式发行在自己的 Cloudflare 账户建立独立实例。参与已有项目无需执行本页。

## 交给 Agent

```text
请用 $cfkanban-deploy 为我部署一套 cfKanban，使用最新正式版和默认基础配置。
Owner 显示名称使用 <你的名称>。先检查环境并展示准确部署计划，再按我的确认执行。
```

需要兼容的 Agent 环境、可持久保存私有状态的用户目录，以及目标 Cloudflare 账户的控制权限。缺少工具或登录时，Agent 会先说明所需准备及其影响，参见 [部署准备](./setup.md)。Owner 显示名称是你选择的身份名称，不会从系统或 Git 用户信息推断。

## 计划中应该看到什么

默认配置包含一个 Worker、一个 D1 数据库、随 Worker 托管的网页，以及 `workers.dev` 地址。文档与网页静态资源随 Service 一起提供。它不自动开启 R2 附件、自定义域名或其他可选产品；实际平台额度与费用以你的 Cloudflare 账户为准。

计划会列明：

- 准确发行版本、来源及校验结果。
- Cloudflare 账户、新 Worker 和 D1 名称，以及确认不存在同名资源的结果。
- Owner 名称、实例标识、迁移内容和访问频率限制。
- 必要的本地安装、凭据保存位置，以及完整部署范围。

如果只有测试版或来源无法验证，Agent 应说明情况；不会自动把测试版、插件缓存或源码工作区当作正式发行。发现同名资源时也不会接管它们。

## 执行与完成标准

确认准确计划后，Agent 创建资源、应用并核对数据库迁移、构建部署配置并验证 Worker 工件，然后部署和初始化 Owner。凭据由安全脚本直接保存到当前环境用户目录中的私有 `~/.cfkanban/`，不需要你复制秘密到聊天。

完成报告应给出可访问的实例地址，以及对实例、Service/schema 版本和 Owner 身份的核对结果。单独的命令成功、公开首页打开或数据库创建成功，都不足以说明整个部署完成。中断时保留原计划与状态，使用 [中断与恢复](./recovery.md) 继续。

**在网页中：** cfKanban 的 Web UI 不创建 Cloudflare 资源。Cloudflare 登录或授权可能在浏览器中完成，但它与 cfKanban 应用登录不同。部署后的网页提供业务管理入口。

## 创建第一个看板

部署只建立实例与 Owner，不自动创建工作区、项目或任务。部署验证完成后，再交给管理技能：

```text
请用 $cfkanban-admin 在 Product 工作区创建 DemoProject 项目，并打开我的第一个看板。
```

Agent 核对 Owner，创建或定位准确工作区和项目，再打开已认证页面。接着可以 [创建任务](../usage/issues.md) 或 [邀请成员](../administration/members.md)。这些应用操作与部署分别执行，具体内容由你的请求决定。

## 常见问题

**安装了插件，为什么还检查发行？** 插件是宿主发现技能的入口，部署必须使用已核验的不可变正式发行工件。

**原来已经有一个实例？** 使用 [接入已有部署](./attach.md)，不要按首次部署重新初始化。

**能把默认部署理解为绝不收费吗？** 默认仅使用核心组件，不代表账户费用担保。可选付费能力、订阅和域名变化会单独说明并获得授权。
