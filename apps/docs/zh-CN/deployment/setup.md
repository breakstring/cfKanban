# 部署准备与技能安装

先检查当前环境，复用兼容工具。只安装技能无需 Cloudflare 登录；只有托管或维护实例才需要云端权限。

## 检查环境

```text
请用 $cfkanban-deploy 只读检查当前环境、Node、Wrangler 和可用正式发行。
说明我可以复用什么，以及部署前还缺少什么。
```

预期得到兼容性与宿主能力报告。Agent 会按目标发行的兼容范围检查 Node 和 Wrangler，不能以“最新版”替代兼容性。已有兼容 Wrangler 或 cfKanban 私有工具运行目录可以复用；缺少时才提出固定版本的安装计划。

你需要能在当前执行环境的用户目录中持久保存私有状态。容器、远端会话或临时环境要先确认保存位置；Windows 原生与 WSL 是独立环境，不会自动共用工具、Cloudflare 登录或凭据。

**在网页中：** 没有环境检查或本地工具安装入口，使用 Agent。缺少 Node 时由你选择安装方式；不会静默修改全局 Node、PATH 或 shell 配置。

## 安装或接入技能

```text
请为当前 Agent 宿主安装 cfKanban 的正式版技能。
核对官方发行、兼容性和安装目录，列出本地影响后按我的授权完成安装与验证。
```

技能包包含三个操作技能：`cfkanban`、`cfkanban-admin`、`cfkanban-deploy`，以及只读讲解技能 `cfkanban-howto`。如果宿主还不能发现部署技能，先通过宿主支持的插件或技能安装流程加载官方入口，再继续发行验证。

安装使用完整已验证技能包，保留共享运行模块和目录结构。cfKanban 的正式技能与维护状态位于私有 `~/.cfkanban/`；宿主自己的插件目录负责发现技能，两者用途不同。不要只复制某个 `SKILL.md` 后假定安装完整。

安装结果需分别说明：正式技能包是否已切换、宿主入口是否已更新、当前 Agent 会话是否已加载新版本。有些宿主需要新开会话才能使用新入口。

## 准备 Cloudflare 权限

```text
请用 $cfkanban-deploy 检查当前可用的 Cloudflare 登录与目标账户。
如需新登录，先展示登录方式、权限和本地影响，再等待我确认。
```

Agent 先复用已确认的维护记录或当前 Wrangler 认证上下文。多个可用账户时由你选择；不会枚举其他登录配置猜测身份。应用 Owner 凭据不能替代 Cloudflare 权限。

需要浏览器登录时，Agent 展示准确权限、登录配置及可能的系统密钥环影响。远端环境的浏览器回调不可达时，要选择受支持的认证路径；不能用不同浏览器或扩大权限绕过失败。不要把 Cloudflare Token、Owner 凭据或 OAuth 结果粘贴到聊天。

**浏览器中的操作：** 在 Cloudflare 官方登录/同意页面核对账户和权限后完成授权。登录成功后，Agent 仍需读回准确账户；这一步不会创建 Worker、D1 或看板。

## 常见问题

**只是加入他人的项目？** 使用 [加入与登录](../usage/access.md)，无需个人 Cloudflare 账户或部署。

**已有插件，是否必须重新安装？** 已有可信兼容版本可复用。Agent 先核对来源、正式安装与宿主加载状态，不为了日常使用强制更新。

**要安装可选 Cloudflare 技能吗？** 它们可辅助平台查询，但不是 cfKanban 部署依赖，不能替代精确发行与计划校验；不会随部署自动安装。
