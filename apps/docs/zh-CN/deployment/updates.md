# 技能更新与实例升级

本地技能和线上站点分别更新。更新技能不会自动升级站点。

## 检查版本

```text
请用 $cfkanban-deploy 检查本地 cfKanban 技能和 <实例地址> 的版本，
说明有哪些兼容的正式版更新，先不要更新。
```

**在网页中：** Owner 可在「管理中心 → 概览 → 服务信息与访问限制」查看站点版本。本机技能版本由 Agent 检查。

## 更新本地技能

```text
请用 $cfkanban-deploy 将本地 cfKanban 技能和当前 Agent 宿主的入口更新到最新兼容正式版。
不要升级线上站点。
```

只需本地安装权限，不需要 Cloudflare 登录。Agent 先识别宿主支持的更新方式，校验发行和兼容性，并保留可恢复的旧版本。支持兼容 Git plugin 或 marketplace 来源的宿主，可跟随默认 `main` 分支，无需每次选择新 tag；本地 Skill 目录安装则更新完整已验证 bundle，保留共享 runtime 和相对路径。两种方式都需要实际更新并核对宿主安装；部分宿主需要新开会话才能加载新技能。

### 将固定旧 tag 的 Git 安装切到默认分支

仅适用于宿主已有固定 tag 的 Git 来源安装，例如 Codex 的 marketplace 注册；本地目录安装无需这项迁移。

```text
请将已注册的 cfKanban Git 安装来源从固定版本 tag 切换到仓库默认分支，并更新宿主安装。
先说明已保存的来源和切换内容，保留我的 cfKanban 身份与部署记录，不要升级线上站点。
```

这是一次性修改已注册的 Git 来源；在 Codex 中，只从过去复制的命令里删掉 `--ref` 不会修改旧设置。Agent 会核对默认分支和实际安装文件与所选正式发行一致；若分支暂时落后最新发行或安装期间发生变化，会说明不一致并重新检查，不会静默改用其他来源。历史版和 RC 仍需明确选择准确 tag。

## 升级线上站点

```text
请用 $cfkanban-deploy 为 <实例地址> 准备升级到最新正式版的计划。
说明版本、数据库变化、预计影响和恢复方案，先让我确认，再执行。
```

需要当前 Owner 身份、Cloudflare 账户权限和本机维护记录。换电脑时先[接入已有部署](./attach.md)。Agent 会说明资源、数据及费用影响；升级完成后核对站点版本、访问能力和原有身份。

站点升级通过 Agent 完成，网页没有升级按钮。若旧技能无法处理新版发行，应先更新本地技能。

## 升级中断或失败

保留维护记录，让 Agent [沿原计划检查并继续](./recovery.md)。不要重新部署空实例，也不要手动删除记录。

回退服务程序不会回退数据库。恢复数据库可能覆盖新数据，需要单独确认；新增费用、域名或权限变化也应先说明。执行使用已确认的版本，不会中途自动换成刚发布的新版。
