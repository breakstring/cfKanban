# 技能更新与实例升级

本地技能和线上 Service 是两条独立更新路径。检查二者不等于更新任意一方；更新技能也不会自动升级实例。

## 只检查版本

```text
请用 $cfkanban-deploy 检查本地 cfKanban 技能、当前会话加载版本和 <实例地址> 的版本。
与最新正式发行比较，说明兼容性，先不要更新。
```

预期得到分别标注的版本与可用更新。Agent 核对正式发行来源和兼容矩阵；旧实例不兼容时，应保留可信兼容技能或提出准确兼容版本，而不是强制升级服务器。

**在网页中：** Owner 可在「管理中心 → 概览 → 服务信息与访问限制」查看实例发行、API 和 schema 版本。网页不能显示所有本地 Agent 的安装或加载版本，也不能直接更新它们。

## 更新本地技能

```text
请用 $cfkanban-deploy 将本地 cfKanban 技能更新到最新兼容正式版。
只更新本地技能与已确认的宿主入口，不升级线上实例。
```

需要本地安装授权，不需要 Cloudflare 登录。Agent 固定并验证目标版本，将完整包安装到独立版本目录，验证后切换，同时保留上一已知良好版本。

预期结果明确区分正式包、宿主投影和当前会话加载。更新宿主入口不代表旧会话已经重新加载；必要时新开会话完成验证。失败时按计划保留或恢复旧版本，不改线上数据库。

## 升级线上实例

```text
请用 $cfkanban-deploy 为 <实例地址> 制定升级到最新正式版的计划。
核对准确资源、当前版本、迁移与恢复依据，展示影响后再由我确认执行。
```

需要准确部署维护记录、当前 Owner 身份及目标 Cloudflare 账户权限。换电脑缺少记录时先 [接入已有部署](./attach.md)。计划列出 Worker/D1、现有绑定、目标工件、数据库迁移、需要时的恢复点依据，以及可选 R2/统计配置的保留情况。

确认后，Agent 核对迁移清单、已应用记录和实际 schema，执行计划中的迁移与 Worker 部署，再读回健康状态、公开发现、Service/schema、实例和未变化的 Owner 身份。现有技能更新仍是独立操作。

**在网页中：** 没有实例升级按钮。管理页面用于升级后的版本与业务验收；部署 Agent 提供远端验证报告。

## 风险与恢复边界

数据库迁移、Worker 代码和静态资源要保持兼容。未知基线、迁移记录或校验摘要漂移、部分应用、意外绑定以及缺少必要恢复证据时，先停止排查。

Worker 回滚不会回滚 D1。D1 恢复可能覆盖数据，不自动执行，也不是升级失败后的默认动作。不兼容变更、资源替换、域名、付费或权限变化需要重新说明准确计划。

## 常见问题

**检查后又发布了新版？** 已批准计划固定一个准确版本；执行时不会偷偷追到另一版，另行评估新目标即可。

**安装显示成功，但 Agent 仍用旧版？** 宿主缓存或当前会话加载可能尚未更新；分别读回并按宿主要求重新开始会话。

**升级中断？** 保留同一计划与维护记录，按 [中断与恢复](./recovery.md) 核对实际状态，不重跑首次部署。
