# 实例升级

本页介绍线上 Cloudflare 站点的升级。Agent 中的本地 cfKanban 安装使用独立[更新流程](../integrations/general.md)，更新它不会升级站点。

## 检查版本

```text
请用 $cfkanban-deploy 检查本地 cfKanban 技能和 <实例地址> 的版本。
说明有哪些兼容的正式版更新，先不要更新。
```

**在网页中：** Owner 可在「管理中心 → 概览 → 服务信息与访问限制」查看站点版本。本地技能和实际运行的集成版本由 Agent 分别核验。

## 更新本地技能

请按[通用 Agent](../integrations/general.md)更新本地技能，并完成所用 Agent 要求的刷新或重启。DeepSeek Harness 用户请看[对应接入指南](../integrations/deepseek-harness.md)。

## 升级线上站点

```text
请用 $cfkanban-deploy 为 <实例地址> 准备升级到最新正式版的计划。
说明版本、数据库变化、预计影响和恢复方案，先让我确认，再执行。
```

需要当前 Owner 身份、Cloudflare 账户权限和本机维护记录。换电脑时先[接入已有部署](./attach.md)。Agent 说明资源、数据与费用影响，保留现有 Cloudflare Observability 设置，升级后核对站点版本、访问能力、日志配置和原有身份。

站点升级通过 Agent 完成，网页没有升级按钮。旧技能无法处理新版发行时，先通过安装与接入指南更新本地技能。

## 补齐已有趋势历史

安装的发行支持 schema 30 或更高版本时，首次 Issue 趋势回填与小时附件/用量历史维护分开执行。需要当前 Owner 身份、Cloudflare 部署权限和已验证的本机维护记录。它只将可恢复历史写入派生统计，不修改 Issue 或增加项目权限；打开图表不会启动回填。

```text
请用 $cfkanban-deploy 检查此实例待处理的趋势历史及当前用量。
使用已验证的实际部署 Service 制定有界首次回填计划，在我的授权内执行。
说明实际 D1 读写、处理进度及仍不可用的历史。
```

Agent 核对剩余额度、固定实际部署和不可变回填算法，逐批记录实际用量。到达预算、用量或结果不确定、限流或漂移时停止。终端使用方式见 [CLI 维护流程](../cli/deployment.md#首次趋势历史回填)。队列清空后，无法重建的旧事件仍可能留下 `partial` 覆盖，详见 [Issue 趋势](../usage/trends.md)。

## 可选的升级公告

Owner 可以开启[升级后自动公告](../administration/settings.md#升级成功后自动发布公告)，默认关闭。兼容 runtime 在实际部署和新发行均读回确认后检查开关，正式版 / `rc.N` 向前升级按发行最多发布一次（alpha、beta 及其他预发行以 `unsupported_channel` 明确跳过）。公告包含实际旧、新版本及 Release 链接，并提供可复制给 Agent 的中英文请求，使用 `cfkanban-deploy` 技能将本地 cfKanban 插件和技能更新到该准确新版本；请求只更新本地，不再次升级站点。站点升级和阅读公告都不会自动更新本地插件或技能。

升级成功与通知结果分别报告。通知失败或结果不确定时，保留原 journal 中准确请求与幂等键，让 Agent 继续原计划或核实原公告；不要再次部署或更换键。安全重放窗口过期后，先核对原操作审计和发行通知证据，再判断后续写入。

## 升级中断或失败

保留维护记录，让 Agent [沿原计划检查并继续](./recovery.md)，不要重新部署空实例或手动删除记录。

回退服务程序不会回退数据库。恢复数据库可能覆盖新数据，需要单独确认；新增费用、域名或权限变化也应先说明。执行使用已确认版本，不会中途自动换成刚发布的新版。
