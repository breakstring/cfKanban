# 快速开始

选择符合当前情况的路径。加入别人的项目不需要自己的 Cloudflare 账户；只有部署自己的实例才需要配置云资源。

## 路径一：加入已有项目

### 1. 使用邀请或公开加入入口

收到项目邀请后，可以把请求交给 Agent：

```text
请用 $cfkanban 加入这个项目：<邀请链接>。
先核对站点、项目、授予的角色和本地身份，再告诉我需要确认的内容。
```

如果站点首页提供公开项目，先选择项目和「只读者」或「协作者」，再复制页面生成的 Agent 提示词。它带有准确站点、项目与指南信息；首次使用时也会引导检查技能是否可用。

Agent 会核对你的身份和权限，再完成加入。邀请链接只交给接收人，不要发布到评论或公开文档。

**网页替代路径：** 已登录的非 Owner 参与者可以打开普通邀请，核对身份后点击「以当前身份接受邀请」。已经通过 Passkey 登录的参与者也可以在首页加入公开项目。首次创建身份与身份恢复仍需要 Agent；详见[加入与登录](../usage/access.md)。

### 2. 打开看板

```text
请用 $cfkanban 在浏览器打开 DemoProject 看板。
```

需要已经加入项目、当前环境有可用的本地身份，并且 Agent 宿主支持浏览器交付。预期进入已登录的目标看板。如果偏好特定浏览器，在请求中写明。

首次进入后，点击顶部自己的名称 →「我的资料」→「登记通行密钥」，根据浏览器或系统提示完成登记。以后可以在该站点首页使用 Passkey 登录。

### 3. 开始处理工作

```text
查看 DemoProject 的待办任务，先不要领取或修改。
```

```text
在 DemoProject 创建“整理登录问题复现步骤”，放入 Backlog，
描述为：收集发生问题的设备、网络条件和错误表现。
```

只读者可以查看，创建或修改需要协作者权限。确认结果后进入[日常使用](../usage/index.md)。如果以后主要从当前目录协作，可以自愿设置[目录关联](../usage/profile.md)。

## 路径二：部署自己的实例

```text
请用 $cfkanban-deploy 检查部署 cfKanban 所需的环境和权限，
为我准备最新正式版的部署计划，展示资源和影响后再执行。
```

需要 Cloudflare 账户及相应权限。默认使用一个 Worker 和一个 D1 数据库；附件和自定义域名等可选配置会单独说明。

**网页说明：** 还没有实例时，网页管理页无法代替部署。准备和执行步骤见[部署](../deployment/index.md)。

部署完成后，再创建第一个工作区和项目：

```text
请用 $cfkanban-admin 在 Product 工作区创建 DemoProject 项目；
如果工作区不存在，先创建它，然后打开项目看板。
```

这一步需要应用内 Owner 或适用的管理权限。新部署的 Owner 可以完成创建；已有工作区的管理员可以在自己范围内创建项目，但不能创建工作区。后续邀请成员和维护设置见[管理](../administration/index.md)。

## 卡住时怎么继续

- Agent 找不到技能：阅读部署栏目中的技能安装说明，先确认当前宿主的安装方式；无需因此另建实例。
- 邀请失效：向有权限的管理员获取新邀请，不把普通项目邀请当作身份恢复工具。
- 浏览器没有打开：让 Agent 检查浏览器交付路径；这不一定意味着身份或凭据失效。
- 只有只读权限：请项目管理员核对你的角色；重新登录不会自动获得写权限。
