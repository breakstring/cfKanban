# 概念与角色

## 实例、工作区、项目与事项

```text
请用 $cfkanban 确认我当前使用的 cfKanban 实例、身份，以及可以访问的项目。
只展示非敏感信息，不修改权限。
```

Agent 需要能使用当前环境中的可信本地身份。预期结果是准确的站点、当前身份和获授权项目，而不是凭据内容。

| 概念 | 含义 |
| --- | --- |
| 实例（Instance） | 一套独立部署的 cfKanban 站点，拥有自己的人员、数据与权限 |
| 工作区（Workspace） | 用于组织多个项目的容器；不是电脑上的文件夹 |
| 项目（Project） | 日常协作的主要范围，有自己的看板、成员、标签和项目描述 |
| 事项（Issue） | 一项可跟踪的工作，如缺陷、需求或讨论，编号形如 `CFK-123` |
| 身份（Principal） | 你在该实例中的稳定身份；改名不会新建身份或改变权限 |
| 负责人（Assignee） | 当前负责一项任务的人；指派不会授予项目权限 |

项目可能同名，查找时可补充所属工作区。不同站点也可能有相同任务编号，跨站点协作时请说明地址。

**在网页中查看：** 顶部显示当前工作区与项目；打开右上角账户菜单查看名称与当前角色，选择「个人设置」查看自己的身份 ID。点击工作区/项目名称可查看当前会话能访问的项目。

## 谁可以做什么

| 身份或权限 | 主要能力 |
| --- | --- |
| 只读者（Reader） | 查看获授权项目、任务、评论、关系和可用附件 |
| 协作者（Writer） | 读取，以及创建、编辑、指派、评论、完成、软删除和恢复项目内容 |
| 项目管理员 | 本项目的内容读写、设置和普通成员管理 |
| 工作区管理员 | 本工作区现有与未来项目的内容读写和管理，可创建项目、管理项目管理员 |
| 所有者（Owner） | 唯一的实例所有者，负责实例级管理、权限、公开加入和恢复等能力 |

协作者不自动成为管理员。普通邀请和公开加入授予只读者或协作者权限，不授予管理身份。部署还需要独立的 Cloudflare 权限；拥有应用内 Owner 身份不等于可以操作云账户。

同一人可以同时拥有普通项目权限与管理员权限。撤销其中一条来源后，其他有效来源仍可能让他继续访问。更多细节见[管理](../administration/index.md)。

## 工作状态与历史

| 固定状态 | 含义 |
| --- | --- |
| Backlog（待规划） | 已记录，还没有承诺近期开始 |
| Todo（待办） | 可以安排或开始的工作 |
| In Progress（进行中） | 正在执行 |
| Done（已完成） | 通过完成操作确认结束，并保存完成记录 |
| Canceled（已取消） | 决定不再执行 |

项目可以改列的显示名称，不能增加第六个状态或改变这些含义。优先级、负责人和阻塞原因与状态各自独立。完成记录不能编辑或删除；重新打开任务后，之前的完成历史仍然保留。

## 登录与访问范围

Agent 使用安全保存的本地身份，网页使用有到期时间的会话。首次可让 Agent 打开已登录看板，再登记 Passkey（通行密钥），以后在同一域名直接网页登录。

切换项目不会增加权限或延长登录有效期。看不到预期项目时，让 Agent 核对访问权限并重新打开，见[加入与登录](../usage/access.md)。
