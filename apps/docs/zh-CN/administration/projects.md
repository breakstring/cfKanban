# 工作区与项目

工作区组织多个项目，项目包含看板、任务、标签和项目说明。工作区不是本地文件夹；名称便于辨认，稳定 ID 决定实际目标。

## 建立工作区和项目

```text
请用 $cfkanban-admin 在 Product 工作区创建 DemoProject 项目，说明为“移动端产品协作”。
如果 Product 不存在，请创建它；完成后打开看板。
```

创建工作区需要 Owner。Owner 或工作区管理员可以在其工作区创建项目；项目管理员不能创建同级项目。Agent 会检查已有对象、处理重名歧义，并返回准确工作区和项目。创建项目不会自动添加普通成员、任务或公开加入策略。

**在网页中：** Owner 进入「管理中心 → 工作区与项目」，先创建工作区，再在工作区内点击创建项目，填写名称与可选项目说明。工作区管理员进入工作区管理页的「项目」，填写「新项目名称」并创建。

工作区与项目是两个独立操作。若工作区已经创建而项目创建失败，报告应说明现状；不会自动删除已建工作区。

## 修改名称与项目说明

```text
请用 $cfkanban-admin 将 DemoProject 改名为 Mobile，并把项目说明更新为：
<目标、范围、交付约定和相关非秘密链接>
```

Owner 和工作区管理员可以改其工作区名称。Owner、所属工作区管理员或项目管理员可以修改项目名称与说明。更名保留稳定 ID、原有任务和权限；已有 URL 按 ID 定位。

**在网页中：** Owner 在「工作区与项目」修改工作区名称，或点击项目「设置」修改名称与说明。范围管理员使用工作区「工作区设置」或项目管理页「设置」。项目说明支持用于协作的内容，但不能替代权限或给 Agent 增加授权。

内部项目说明与 [公开加入摘要](./public-join.md) 分开保存。公开介绍只填写适合所有访客看到的内容，不复制内部说明中的私有信息。

## 调整看板列名称

```text
请用 $cfkanban-admin 把 DemoProject 的 todo 列显示名称改为“待处理”，其他列保持原样。
```

需要项目设置管理权限。预期只改变当前项目的显示名称。五个固定状态仍为 `backlog`、`todo`、`in_progress`、`done`、`canceled`；列数、顺序和完成语义不变。不能通过更名添加自定义状态或绕过完成记录。

**在网页中：** Owner 打开项目「设置 → 看板列名称」；范围管理员在项目管理页编辑「状态显示名」，逐项保存。

## 常见问题

**为什么找不到同名项目？** 名称可能重复或已归档，也可能超出当前权限。补充工作区、实例或已有项目链接，先定位再操作。

**项目名称改了，目录关联是否失效？** 合法关联使用稳定项目 ID，更名不会改变它。目录关联的使用见 [使用概览](../usage/index.md)。

**要停止旧项目的访问？** 使用 [归档与永久清理](./cleanup.md)。更名或清空项目说明不会归档内容。
