# 工作区与项目

工作区组织多个项目；每个项目有自己的看板、任务、标签和描述。

## 建立工作区和项目

```text
请在 Product 工作区创建 DemoProject 项目，说明为“移动端产品协作”。
如果 Product 不存在，请先创建它。
```

创建工作区需要 Owner。Owner 或工作区管理员可以在其工作区创建项目；项目管理员不能创建同级项目。Agent 会检查已有对象、处理重名歧义，并返回准确工作区和项目。创建项目不会自动添加普通成员、任务或公开加入策略。

**在网页中：** Owner 进入「管理中心 → 工作区与项目」，点击「新建工作区」，再在对应工作区行点击「新建项目」，填写名称与可选项目说明。工作区管理员进入工作区管理页的「项目」，填写「新项目名称」并创建。

展开工作区查看项目。点击项目名称进入看板，「工作区设置」直接打开工作区管理页的设置标签，「项目设置」进入完整项目设置页。工作区管理页还可切换至「项目」或「成员与权限」标签。项目说明显示在名称下方。行末的更多操作菜单收纳低频操作：工作区重命名与归档、项目公开加入与归档。从此列表打开设置后，点击「返回管理中心」回到列表并展开来源工作区。

项目设置将「项目管理」与「成员与权限」分为独立标签。项目管理维护项目说明、名称、列显示名及归档或恢复；成员与权限集中管理员、有效成员与权限来源、直接成员授权及项目邀请。可见标签和操作仍按当前权限提供。

## 修改名称与项目说明

```text
请将 DemoProject 改名为 Mobile，并把项目说明更新为：
<目标、范围、交付约定和相关非秘密链接>
```

Owner 和工作区管理员可以修改相应工作区名称；项目名称和描述也可由项目管理员修改。更名不会改变任务和权限。

**在网页中：** Owner 在「工作区与项目」打开对应工作区的更多操作菜单 →「重命名工作区」，或从「项目设置 → 项目管理 → 设置」修改项目名称与说明。范围管理员使用工作区「工作区设置」，或从看板进入「项目设置 → 项目管理 → 设置」。项目说明支持用于协作的内容，但不能替代权限或给 Agent 增加授权。

内部项目说明与 [公开加入摘要](./public-join.md) 分开保存。公开介绍只填写适合所有访客看到的内容，不复制内部说明中的私有信息。

## 调整看板列名称

```text
请把 DemoProject 的待办列显示名称改为“待处理”，其他列保持原样。
```

需要项目管理权限。修改只影响列的显示名称，Backlog、待办、进行中、已完成、已取消五种状态及其顺序不变。

**在网页中：** 打开「项目设置 → 项目管理」，编辑「状态显示名」并逐项保存。Owner 可从「工作区与项目」进入项目设置；范围管理员从有权管理的看板进入。

## 常见问题

**为什么找不到同名项目？** 名称可能重复或已归档，也可能超出当前权限。补充工作区、实例或已有项目链接，先定位再操作。

**项目名称改了，目录关联是否失效？** 不会。关联使用不随名称变化的项目 ID。详见[目录关联](../usage/profile.md)。

**要停止旧项目的访问？** 使用 [归档与永久清理](./cleanup.md)。更名或清空项目说明不会归档内容。
