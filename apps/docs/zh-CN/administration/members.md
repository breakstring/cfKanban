# 成员、邀请与管理员

使用 `cfkanban-admin` 邀请协作者，并区分普通项目权限与管理权限。

## 创建项目邀请

```text
请为 Product 工作区的 DemoProject 创建一个只读邀请，我会转发给接收人。
```

需要 Owner、所属工作区管理员或该项目管理员权限。普通邀请只授予 `reader`（只读）或 `writer`（协作）权限，不能邀请对方成为管理员。局部管理员每次只能邀请一个受管项目；Owner 可以在一次邀请中指定多个项目及各自角色。

邀请固定有效 7 天，只能兑换一次。Agent 会读回邀请状态；默认把一次性邀请话术复制到剪贴板，完整链接不会出现在普通输出中。创建邀请不代表已替你发送给他人。若环境无法安全交付，先解决交付方式，不把链接保存到任务、日志或公开文档。

**在网页中：** Owner 打开「管理中心 → 成员与权限 → 邀请」，选择项目与角色并保存，然后复制一次性邀请并点击「我已保存，完成」。范围管理员从对应看板进入「项目设置 → 成员与权限」，在项目邀请区域选择角色并创建。邀请历史可查看状态和撤销未兑换邀请；历史记录不能重新显示已交付的秘密链接。

接收人使用 [加入与登录](../usage/access.md) 的流程。已登录的非 Owner 参与者可以在支持此功能的网页核对当前身份后接受普通邀请；新身份、身份恢复和 Owner 接入由相应 Agent 流程完成。

## 查看或调整成员权限

```text
请列出 DemoProject 的成员及各自的权限来源。
```

```text
请将 DemoProject 中 <成员名称> 的普通项目权限改为 reader。
若此人还有管理员权限，请先说明实际剩余访问能力。
```

需要与创建邀请相同的管理权限；遇到同名或不明确的成员，先核对准确对象。

**在网页中：** Owner 可在「成员与权限 → 项目成员权限」选择项目，或从「工作区与项目 → 项目设置 → 成员与权限」进入。在项目的「成员与权限」标签中，「有效成员与权限来源」显示来源，「直接成员授权」提供姓名搜索、角色修改、移除和重新授予。候选列表中没有的新成员通过邀请加入。

权限按有效来源合并。移除普通授权不会移除项目管理员或继承的工作区管理员权限；授予 `reader` 也不会降低已有管理权限。若要移除所有访问，先检查所有来源。仍开启公开加入的项目允许被移除者再次加入。

## 任免管理员

```text
请将 <成员名称> 设为 Product 工作区管理员。
先说明这会覆盖哪些现有项目，以及未来项目的继承权限。
```

```text
请将 <成员名称> 设为 DemoProject 的项目管理员。
```

Owner 任免工作区管理员；Owner 或所属工作区管理员任免项目管理员。同级管理员不能互相任免。工作区管理员管理现在和未来的全部子项目，项目管理员只管理本项目。每个范围可以有多位管理员，也可以没有局部管理员而由上级管理。

**在网页中：** 打开工作区管理页的「成员与权限」，或「项目设置 → 成员与权限」，在「管理员」区域按姓名选择人员，核对影响并授予或撤销。普通 reader/writer 可以被提升；已有管理权限者不会再次出现在添加候选中。

公开项目的人数配额包含非 Owner 管理员，同一人只计一次。添加工作区管理员若会使任一受影响的公开项目超额，整次授权失败。不会只给部分项目授权。

## 邀请失效与撤权

```text
请撤销 DemoProject 的未兑换邀请 <邀请记录 ID>。
```

签发者失去原管理权限时，其未使用的邀请可能永久失效，需要重新邀请。已经加入的成员不因此自动移除。

需要恢复同一个人的身份时，使用 [设备与身份恢复](./devices.md)，普通邀请不能替代恢复邀请。
