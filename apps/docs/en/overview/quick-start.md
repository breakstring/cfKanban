# Quick start

Choose the path that matches your situation. Joining someone else's project does not require your own Cloudflare account. Cloud resources are needed only when you host an instance yourself.

## Path one: join an existing project

### 1. Use an invitation or Public Join

If you received a project invitation, ask an Agent:

```text
Use $cfkanban to join this project: <invitation link>.
First check the site, projects, granted roles, and local identity, then explain what I need to confirm.
```

If the site's homepage lists public projects, select a project and Reader or Writer, then copy the Agent prompt generated by the page. It includes the exact site, target, and joining guide, including a check for available Skills on first use.

The Agent checks your identity and access before completing the join. Share invitation links only with their recipients, not in comments or public documents.

**Web alternative:** An already signed-in non-Owner participant can open an ordinary invitation, verify their identity, and explicitly accept it as that identity. A participant signed in with a Passkey can also join a public project from the homepage. Creating a first identity and recovering one still require the Agent path. See [Joining and signing in](../usage/access.md).

### 2. Open the board

```text
Use $cfkanban to open the DemoProject board in my browser.
```

You need project access, a usable local identity in the current environment, and an Agent host that supports browser delivery. Expect an authenticated board for the requested project. Name a particular browser if you have a preference.

On your first visit, select your name in the header → **My profile** → **Register Passkey**, then complete the browser or system prompt. You can subsequently sign in with that Passkey from the same site's homepage.

### 3. Start working

```text
Show the Todo issues in DemoProject without claiming or changing any of them.
```

```text
Create “Document login reproduction steps” in DemoProject and put it in Backlog.
Description: Collect the affected devices, network conditions, and error symptoms.
```

Readers can view issues; creating or changing them requires writer access. Continue with [daily use](../usage/index.md) after checking the result. If you regularly work from one folder, an optional [directory association](../usage/profile.md) can save you from repeating the project name.

## Path two: host your own instance

```text
Use $cfkanban-deploy to check the environment and permissions needed to deploy cfKanban.
Prepare a plan for the latest stable release and show me the resources and effects before executing it.
```

You need a Cloudflare account and the appropriate authority. The default uses one Worker and one D1 database; attachments, custom domains, and other options are explained separately.

**Web note:** Before an instance exists, its management pages cannot perform the deployment. See [Deployment](../deployment/index.md) for preparation and execution.

After deployment, request your first workspace and project:

```text
Use $cfkanban-admin to create DemoProject in the Product workspace.
If the workspace does not exist, create it first, then open the project board.
```

This requires application Owner access or the appropriate administrative scope. The Owner of a new deployment can create both. An existing workspace's administrator can create projects in that workspace but cannot create a workspace. Continue to [Administration](../administration/index.md) for invitations and settings.

## If you get stuck

- **The Agent cannot find the Skill:** Follow the Skill installation guidance in Deployment for your host. You do not need another instance just to install a Skill.
- **An invitation is invalid:** Request a new invitation from an authorized administrator. Ordinary project invitations do not recover an existing identity.
- **The browser did not open:** Ask the Agent to check browser delivery. A handoff failure does not necessarily mean the identity or credential is invalid.
- **You have reader access:** Ask a project administrator to check your role. Signing in again does not grant write access.
