# cfKanban 1.10.1-rc.7

## 简体中文

相对已公开的 `1.10.1-rc.6`，本 RC 简化 Owner 的 Cloudflare 设置和用量查看，保留旧操作恢复，并修复域名回退后的升级阻断。

- Cloudflare Token 只需点击「保存」，系统自动核对保存结果、配置与统计能力并加载数据；已保存状态持续可见，单项能力失败不会撤销保存成功。
- 「用量与配额」集中展示 UTC 当日用量、每日历史和附件容量，底部可逐项调整访问频率；Paid 方案也使用真实日窗口，账期累计收在数据详情。
- 首页实例说明移入「实例设置」，概览保留只读摘要，日常查看与修改入口更清楚。
- 退役新的 WAF 配置、用量阈值和预算通知管理，保留旧操作的读回恢复及已核验归属规则的受控清理。
- 已回退的域名被其他 Worker 复用时不再阻断原实例升级；原 Worker 仍有域名映射或入口配置漂移时继续拒绝升级。

## English

Compared with published `1.10.1-rc.6`, this RC simplifies Owner Cloudflare settings and usage views, preserves recovery of existing operations, and fixes an upgrade blocker after domain rollback.

- Saving a Cloudflare Token automatically verifies the save result, checks configuration and analytics access, and loads data. The saved status stays visible, and an individual capability failure does not undo a successful save.
- Usage & quotas brings UTC daily usage, daily history, and attachment capacity together, with individual request-frequency controls below. Paid plans also use actual daily windows; billing-cycle totals remain in data details.
- Homepage description editing moves to Instance settings, while Overview keeps read-only summaries, making viewing and editing easier to find.
- New WAF configuration, usage-threshold settings, and budget-notification management are retired. Existing operations retain readback and recovery, with controlled cleanup of rules whose ownership has been verified.
- Reuse of a rolled-back hostname by another Worker no longer blocks upgrades of the original instance. Domain mappings that still point to the original Worker or drift in its access settings continue to block upgrades.

## 升级与已知限制 / Upgrade and known limitations

从 `1.10.1-rc.6` 升级无新增 migration，schema 保持 **27**，API 保持 **0.1.0**；升级前仍需核对实际 migration ledger 与 schema。升级不会自动删除已有 WAF 规则；规则清理须另行核验归属并按获准计划执行。写入回执未知时继续保留原请求与安全锁，必须核对原操作后才能继续。

Upgrading from `1.10.1-rc.6` adds no migration: schema remains **27** and API remains **0.1.0**. Verify the actual migration ledger and schema before upgrading. Existing WAF rules are not automatically deleted; cleanup requires separate ownership verification and an approved plan. When a write outcome is unknown, the original request and safety lock remain in place until the original operation is checked.
