# cfKanban 0.1.0-alpha.22

Testing prerelease / 测试发行版

## English

This testing prerelease completes the first large-record and concurrent-write recovery pass found through live dogfooding.

Changes:

- continues active and deleted Issue, Comment, Label, Relation, Principal, Credential, Grant, Invitation, Audit, and public Project lists with bound cursors instead of silently stopping at the first page;
- retires invalid or scope-mismatched cursors with an explicit recovery message;
- gives Issue, Comment, Label, Relation, container, Grant, Public Join Policy, profile, Credential, and Passkey writes one shared version-conflict presentation that retains the local draft, reads back current facts, and requires a fresh decision;
- fences repeated Web submissions so a double click cannot start a second copy of the same write;
- renders structured completion summaries, verification, artifacts, and follow-ups while retaining a safe fallback for older or malformed records;
- verifies that two completion records remain visible after complete, reopen, complete, and API reload.

The REST API and D1 schema are unchanged from alpha.21. The Service bundle changes because the Web UI and its compiled Static Assets change.

Important limits:

- this is not the stable channel and must be selected explicitly;
- Skill update and Instance upgrade remain separate plans;
- bounded Workspace/Project tree projections and nested Principal Grant/Passkey projections still report explicit Agent fallbacks where no continuation endpoint exists.

Install the tagged plugin:

```text
codex plugin marketplace add https://github.com/breakstring/cfKanban.git --ref 0.1.0-alpha.22
codex plugin add cfkanban-agent-skills@cfkanban
```

## 简体中文

这次测试发行补齐了真实 dogfooding 中发现的第一轮大记录量与并发写入恢复体验。

变更：

- 对 active/已删除 Issue、Comment、Label、Relation，以及 Principal、Credential、Grant、Invitation、Audit 和公开 Project 使用绑定 cursor 连续读取，不再静默停在第一页；
- cursor 失效或查询范围不匹配时，会停止使用旧 cursor 并显示明确恢复提示；
- Issue、Comment、Label、Relation、容器、Grant、Public Join Policy、资料、Credential 与 Passkey 写入共用一致的版本冲突展示：保留本地草稿、读回服务端事实，并要求重新判断后再提交；
- 为 Web 写入增加重复提交栅栏，双击不会启动同一写入的第二份请求；
- 结构化展示完成摘要、验证、产物与后续，同时为旧记录或异常记录保留安全降级；
- 验证 Issue 在完成、重开、再次完成并重新读取 API 后，两条完成记录仍完整可见。

REST API 与 D1 schema 相对 alpha.21 没有变化。由于 Web UI 及其编译后的 Static Assets 发生变化，Service bundle 会更新。

重要限制：

- 这不是 stable channel，必须由用户明确选择；
- Skill update 与 Instance upgrade 仍是两份独立计划；
- Workspace/Project 树，以及 Principal 详情中的 Grant/Passkey 投影，在没有 continuation endpoint 时仍会明确提示改用 Agent。

安装带 tag 的 plugin：

```text
codex plugin marketplace add https://github.com/breakstring/cfKanban.git --ref 0.1.0-alpha.22
codex plugin add cfkanban-agent-skills@cfkanban
```
