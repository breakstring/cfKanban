# cfKanban 1.12.0-rc.7

## 简体中文

相对 `1.12.0-rc.6`，本 RC 新增 Issue 趋势与里程碑燃起图，帮助查看工作积压、每日变化和交付进度。

- 在项目的“趋势”视图查看未完成事项存量及每日新增、完成次数，并选择最近 30、90 或 365 天。
- 从工作区入口汇总当前可访问项目，也可选择需要统计的项目范围。
- 从里程碑列表的“查看趋势”进入燃起图，查看范围变化与已完成存量，并联动筛选其他趋势图。
- Agent、公共 CLI 与 Web 使用一致统计口径；已有可恢复历史分批补齐，未知日期保留断点。

## English

Compared with `1.12.0-rc.6`, this RC adds Issue trends and milestone burn-up charts to show outstanding work, daily changes, and delivery progress.

- Open a project's Trends view to see unfinished stock and daily creation and completion counts over 30, 90, or 365 days.
- Aggregate currently accessible projects from the workspace entrypoint, with an optional project selection.
- Open View trends from a milestone row to see changing scope and completed stock, with the other charts filtered to that milestone.
- Agents, the public CLI, and Web share the same counting rules; recoverable history is filled incrementally and unknown dates remain gaps.

## 升级与已知限制 / Upgrade and known limitations

新增兼容迁移 `0029_issue_trends.sql`，schema 从 28 升至 29，API 兼容版本仍为 0.1.0。升级会冻结已有状态并启用共享小时维护计划，按有界批次补齐历史；无法验证的旧历史显示缺失。图表按 UTC 日计件，完成次数包含重开后的再次完成；不提供理想燃尽线或工时估算。升级前仍须核对真实 ledger/schema 和恢复点。

Adds the compatible `0029_issue_trends.sql` migration, upgrading schema 28 to 29 while API compatibility remains 0.1.0. The upgrade freezes existing state and enables shared hourly maintenance to fill history in bounded batches; unverifiable history stays missing. Charts count Issues per UTC day, and completion counts include completion after reopening. Ideal burndown lines and effort estimates are outside this release. Verify the actual ledger/schema and restore point before upgrading.

范围与统计口径 / Scope and counting rules: [CFK-715](https://cfkanban.dev/app/issues/CFK-715).
