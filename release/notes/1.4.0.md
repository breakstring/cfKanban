# cfKanban 1.4.0

## 简体中文

本正式版相对 `1.3.0` 新增站内双语文档、更多事项筛选方式和查询索引，并简化看板。相对 `1.4.0-rc.2`，进一步精简用户文档、调整看板布局，并将项目活动和已删除事项移到独立页面。

- 同实例 `/docs/` 提供 English / 简体中文手册，按概述、使用、管理、部署组织，支持搜索、语言切换及可复制给 Agent 的示例话术。说明以用户目标和网页操作为主，保留权限、费用和数据影响等必要提醒；文档随实例版本更新，无需额外部署服务。
- 已登录网页提供文档、GitHub 和产品版本页脚。文档在新标签页打开，无需退出当前账号。Howto 技能可查阅目标实例的相关文档并引用来源，遇到文档缺失或版本不匹配时说明限制。
- Web 看板、工作清单及 Agent 支持优先级和标签多选筛选，普通任务列表也可筛选未分配事项。同类条件匹配任一选项，不同类别组合使用；筛选在服务端分页前完成。
- 看板直接展示项目描述，优先级和标签改为紧凑下拉菜单，选择后自动更新结果。标题搜索仍通过搜索按钮或 Enter 提交；打开项目活动、已删除事项再返回时保留已应用的筛选。
- 项目活动与已删除事项使用独立页面，支持继续加载；有权限的用户可在已删除页面逐项恢复。桌面与窄屏的页头和筛选布局同步调整。
- 查询按状态、负责人、优先级等条件使用相应索引，减少部分常见查询对无关事项的读取。索引会增加存储和相关写入成本；实际读取量仍取决于筛选组合和匹配数据量，不保证固定额度消耗。
- OpenAPI 的 `info.version` 跟随产品发行版本，API 兼容版本继续独立维护。
- 修复看板访问错误被标签清空操作隐藏的问题；关闭恢复操作的版本冲突提示后，较晚返回的检查结果不会再次弹出同一提示。

## English

Compared with `1.3.0`, this stable release adds bilingual instance documentation, more Issue filters and query indexes, and a simpler board. Changes since `1.4.0-rc.2` further simplify user documentation, refine the board layout, and move project activity and deleted Issues to dedicated pages.

- English and Simplified Chinese documentation is available at `/docs/` on the same instance, organized into overview, usage, administration and deployment. It includes search, language switching and copyable Agent prompts. Guidance focuses on user goals and Web actions while retaining relevant permission, cost and data-impact information. Documentation updates with the instance and needs no additional service.
- Signed-in pages provide a shared footer with documentation and GitHub links and the product version. Documentation opens in a new tab without signing out. The Howto Skill can consult relevant documentation on the selected instance, cite its sources and explain missing pages or version mismatches.
- Web boards, work lists and Agents support multiple priority and label filters. Ordinary task lists can also select unassigned Issues. Values within a category match any selected option; different categories combine. Filtering runs on the server before pagination.
- The board displays the project description directly. Compact priority and label menus update results automatically after selection. Title search still requires the Search button or Enter; applied filters survive visits to project activity or deleted Issues and the return to the board.
- Project activity and deleted Issues have dedicated pages with pagination. Authorized users can restore individual Issues from the deleted-Issues page. Header and filter layouts also improve on desktop and narrow screens.
- Queries use indexes suited to conditions such as status, assignee and priority, reducing unrelated Issue reads for some common queries. Indexes add storage and write costs; actual reads still depend on the filter combination and matching data, so fixed quota consumption is not guaranteed.
- OpenAPI `info.version` follows the product release while the API compatibility version remains independent.
- Board access errors no longer disappear when selected labels are cleared indirectly. After a restore-conflict notice is dismissed, a late readback cannot reopen that same notice.

## 升级说明 / Upgrade notes

从 `1.3.0` 升级时，部署工具须先应用 `0013_issue_query_indexes.sql`，将 schema 从 `12` 升至 `13`，再部署新版 Worker；不能跳过迁移。该迁移新增四个索引，不改写业务行，旧索引保留。已升级至 schema `13` 的 `1.4.0-rc.1` / `1.4.0-rc.2` 实例无需新增迁移。API 兼容版本保持 `0.1.0`。Worker 回滚不会回退数据库。

When upgrading from `1.3.0`, the deployment tool must apply `0013_issue_query_indexes.sql` to advance schema `12` to `13` before deploying the new Worker. Do not skip this migration. It adds four indexes without rewriting business rows, and retains existing indexes. Instances on `1.4.0-rc.1` / `1.4.0-rc.2` that already use schema `13` require no additional migration. The API compatibility version remains `0.1.0`. A Worker rollback does not roll back the database.

本版发行清单使用 manifest schema `2`。先更新到支持此格式的 Skills 和宿主插件，再升级实例；不要绕过旧技能对未知格式的拒绝。新版部署技能继续支持历史清单和 Service 工件。本机技能更新与实例升级需分别执行；插件文件更新也不代表已打开的 Codex 对话已重新加载。

This release uses manifest schema `2`. Update to compatible Skills and host plugins before upgrading an instance; do not bypass an older Skill's rejection of an unknown format. The new deployment Skills continue to support historical manifests and Service bundles. Local Skill updates and instance upgrades are separate operations; updated plugin files do not establish that an open Codex conversation has reloaded them.

发行提交的完整源码检查、工件校验与线上读回结果由发版 Issue 记录。本地浏览器检查使用隔离模拟数据，不代表全部浏览器或线上业务场景均已验证。

Full source checks, artifact verification and live readback for the release commit are recorded in the release Issue. Local browser checks use isolated mock data and do not establish coverage of every browser or live business scenario.
