# cfKanban 1.10.1-rc.2

## 简体中文

相对已公开的 `1.10.1-rc.1`，本 RC 让 Owner 在网页安全接入 Cloudflare 管理授权、核实配置与防护状态，并按需查看日度用量趋势。

- Owner 可先预览再应用用量设置和原生频率限制，使用部署固定的账户、Worker 与数据库目标。
- 网页提供官方 Token 创建与最小权限指引，分别将配置、只读管理及统计授权保存到 Worker Secrets，供 Owner 跨设备使用。
- 保存或应用结果未知时保留原操作并核实，避免盲目重发；升级保留线上限流、用量配置及三个已配置 Secret。
- 主动只读核验通知策略与所选 Zone 的 WAF 状态，区分权限不足、读取失败和未配置，明确无法确认的 USD 预算合同。
- 可选日度历史展示最近 7、30、90 个完整 UTC 日，保留指标来源、实例与账户范围、缺日和未知值，便于比较可用的用量趋势。

## English

Compared with published `1.10.1-rc.1`, this RC lets Owners safely connect Cloudflare management authorization in the browser, verify configuration and protection status, and inspect daily usage trends when enabled.

- Owners can preview and apply usage settings and native rate limits against the account, Worker and database fixed by the deployment.
- The browser provides official Token creation and least-privilege guidance, saving configuration, read-only management and analytics authorization separately in Worker Secrets for use across Owner devices.
- Unknown save or apply outcomes retain the original operation for verification, avoiding blind replay; upgrades preserve live rate limits, usage configuration and all three configured Secrets.
- On-demand read-only checks inspect notification policies and WAF status for the selected Zone, distinguishing denied permission, failed reads and missing configuration while making the unconfirmed USD budget contract explicit.
- Optional daily history shows the latest 7, 30 or 90 complete UTC days, preserving metric sources, instance and account scopes, missing dates and unknown values for comparison of available usage trends.

## 升级与已知限制 / Upgrade and known limitations

从 `1.10.1-rc.1` 升级包含两项兼容 migration（0025–0026），新增用量派生历史及管理操作记录，schema **24→26**，API 保持 **0.1.0**。升级前须核对实际 ledger/schema、D1 恢复点与线上配置。Owner 须自行在 Cloudflare 创建适用 Token，并在当前实例网页输入；配置授权的单 Worker Editor 权限包含代码修改与部署权。

Upgrading from `1.10.1-rc.1` includes two compatible migrations (0025–0026), adding derived usage history and management operation records, moving schema **24→26** while keeping API **0.1.0**. Verify the actual ledger/schema, D1 restore point and live configuration before upgrading. Owners must create suitable Tokens in Cloudflare and enter them in the current instance's browser page; the configuration Token's single-Worker Editor permission includes code changes and deployment.

历史采集默认关闭，开启后复用已有维护触发器，不新增默认 Cron；无触发器时可手动采集最近七个完整 UTC 日中的一天。USD 预算金额和收件邮件编辑尚未实现，请使用 Cloudflare 官方控制台。用量为 Analytics 观测，不是最终账单或费用封顶；实际 Token 接入、线上控制面效果与各宿主加载须分别验收。

History collection is disabled by default and reuses an existing maintenance trigger when enabled, without adding a default Cron; instances without a trigger can manually collect one of the latest seven complete UTC days. Editing USD budget amounts and recipient emails is not implemented; use the official Cloudflare dashboard. Usage represents Analytics observations rather than final invoices or spending caps; actual Token setup, live control-plane effects and loading in each host require separate verification.
