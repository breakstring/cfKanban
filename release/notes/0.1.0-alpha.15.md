# cfKanban 0.1.0-alpha.15

Testing prerelease / 测试发行版

## English

This testing prerelease fixes the canonical Skill update path after a real update rehearsal found that receipts written by the installer and receipts expected by the continuity checker had different publisher shapes.

Changes:

- accepts both the installed string publisher shape and the structured canonical-origin shape when checking release continuity;
- derives the previous artifact origin from the receipt's exact HTTPS source URL when an older receipt has no `artifact_origins` array;
- writes normalized publisher/source values and explicit artifact-origin evidence into newly installed receipts;
- keeps the comparison fail-closed for malformed receipts, non-HTTPS sources, changed publishers, and artifact origins outside the target manifest allowlist;
- adds a regression that installs a bundle, reads the actual generated receipt, and proves same-source continuity plus the main rejection boundaries;
- retains alpha.14's Workspace-lowercase and Project-uppercase interaction normalization.

The correction changes only the Skill bundle and release documentation. An already deployed compatible Service does not need to be upgraded.

Important limits:

- this is not the stable channel and must be selected explicitly;
- it supersedes alpha.14 for Skill updates because alpha.14 can falsely report a source change for a receipt created by its own installer;
- broader Web concurrency, target-scope, pagination, and browser hardening remain release-candidate work;
- host or operating-system permission prompts remain independent of cfKanban's application-level authorization.

Install the tagged plugin:

```text
codex plugin marketplace add https://github.com/breakstring/cfKanban.git --ref 0.1.0-alpha.15
codex plugin add cfkanban-agent-skills@cfkanban
```

Start a new Codex task and say:

```text
Use $cfkanban-admin to create my first cfKanban board.
```

## 简体中文

这次测试发行修复 canonical Skill 更新链路：真实更新演练发现，安装器写出的 receipt 与连续性检查器期望的 publisher 结构不一致。

变更：

- 连续性检查同时接受已安装的字符串 publisher 与结构化 canonical origin；
- 较早 receipt 没有 `artifact_origins` 数组时，从其中准确的 HTTPS source URL 推导原 artifact origin；
- 新安装的 receipt 会写入规范化的 publisher/source 与显式 artifact-origin 证据；
- 对畸形 receipt、非 HTTPS source、publisher 变化和 target manifest allowlist 之外的 artifact origin 继续严格停止；
- 新增回归：先真实安装 bundle，再读取安装器生成的 receipt，验证同源连续性和主要拒绝边界；
- 保留 alpha.14 的 Workspace 小写、Project 大写交互层规范化。

本次修正只改变 Skill bundle 与发行文档；已经部署的兼容 Service 无需升级。

重要限制：

- 这不是 stable channel，必须由用户明确选择；
- Skill 更新应使用本版本取代 alpha.14，因为 alpha.14 会把自己安装器生成的 receipt 误报为来源变化；
- Web 并发、target scope、分页与浏览器加固仍属于 release candidate 工作；
- Agent 宿主或操作系统自己的权限提示仍独立于 cfKanban 应用层授权。

安装带 tag 的 plugin：

```text
codex plugin marketplace add https://github.com/breakstring/cfKanban.git --ref 0.1.0-alpha.15
codex plugin add cfkanban-agent-skills@cfkanban
```

新建 Codex 任务后只需要说：

```text
请使用 $cfkanban-admin 创建我的第一个 cfKanban 看板。
```
