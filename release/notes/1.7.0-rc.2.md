# cfKanban 1.7.0-rc.2

## 简体中文

相对 `1.7.0-rc.1`，本 RC 增加 Kanban 卡片负责人下拉选择，让分配工作更直接。

- **直接分配负责人**：在卡片底部选择当前项目有资格的人员，更换或取消分配，保持事项状态不变。
- **按需加载人员**：同一看板共享候选列表，需要时分页加载，不为每张卡片重复查询。
- **保留可靠保存反馈**：只读者仍只看到负责人；保存、冲突及结果不确定时复用当前权限、版本和核实流程，保留历史负责人信息。

## English

Compared with `1.7.0-rc.1`, this RC adds an assignee selector to Kanban cards for more direct assignment.

- **Assign from the card**: Choose an eligible person in the current project, change the assignee, or clear the assignment without changing issue status.
- **Load people as needed**: Cards share one candidate list per board, with additional pages loaded on demand instead of repeated queries for each card.
- **Keep reliable save feedback**: Readers retain the assignee display. Saving, conflicts, and uncertain results use the existing permission, version, and verification flow while preserving historical assignee information.

## 升级与已知限制 / Upgrade and known limitations

从 `1.7.0-rc.1` 升级没有新增 migration，schema 保持 **18**，API 保持 **0.1.0**。从正式版 `1.6.0` 升级仍需先应用 `0018_read_query_indexes.sql`，再部署 Worker；Worker 回滚不会回退 D1。普通安装仍推荐 stable，实例升级与 Skill 更新独立执行。

人员候选仅表示读取时有资格，保存时仍由服务端复核。历史负责人失去写入资格时保留引用，可由有权限的人重新选择或清除；不会自动替换。大规模数据的线上计费读量不由本次 UI 验收证明。

Upgrading from `1.7.0-rc.1` adds no migration: schema remains **18** and the API remains **0.1.0**. Upgrades from stable `1.6.0` still require `0018_read_query_indexes.sql` before Worker deployment. Worker rollback does not roll back D1. Regular installations should use stable; instance upgrades and Skill updates are independent.

Candidates are eligible at read time; the server checks eligibility again when saving. Historical assignments remain when eligibility is lost, and authorized users can change or clear them. No replacement happens automatically. This UI verification does not establish billed read costs at large scale.
