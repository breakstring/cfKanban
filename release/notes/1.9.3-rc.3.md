# cfKanban 1.9.3-rc.3

## 简体中文

相对 `1.9.3-rc.2`，本 RC 增加编号前缀与标题搜索，并用本机持久缓存减少输入时的网络等待。

- 搜索入口提供 `cfkanban-search` 名称与说明，可输入完整编号、部分编号或标题关键词，最多展示十条事项候选。
- 本地 SQLite 缓存按服务实例与用户隔离，重启后直接复用；候选查询无需逐次等待网络核权。
- 后台同步事项新增、改名、删除和恢复；新获得项目权限时补齐历史事项，撤权后清理缓存。
- 增加请求合并、限流与取消控制，并同步公共 CLI 和双语使用指引。

## English

Compared with `1.9.3-rc.2`, this RC adds number-prefix and title search, using a persistent local cache to reduce network waits while typing.

- The search entry supplies the `cfkanban-search` name and description, accepting complete identifiers, number prefixes, or title keywords and returning up to ten Issue candidates.
- A local SQLite cache is isolated by service instance and user and reused after restart; candidate queries do not wait for a network permission check on every input.
- Background synchronization tracks creation, renaming, deletion, and restoration, backfills existing Issues after a new Project grant, and removes revoked Projects.
- Adds request coalescing, rate limits, and cancellation controls, with matching public CLI commands and bilingual usage guidance.

## 升级与已知限制 / Upgrade and known limitations

新增 additive migration `0020_issue_search_index.sql`，schema 从 **19** 升到 **20**，API 保持 **0.1.0**。本地组件与 Service 都需升级；明确选择 `1.9.3-rc.3`，核对实际 MCP 工件路径并重启宿主。仅搜索编号和标题，不搜索正文或评论；选中引用后的详情读取仍实时核权。

Adds the additive migration `0020_issue_search_index.sql`, advancing schema from **19** to **20** while retaining API **0.1.0**. Upgrade both local components and the Service, explicitly select `1.9.3-rc.3`, verify the actual MCP artifact path, and restart the host. Only identifiers and titles are searched; bodies and Comments are excluded, and selected references still read details under live authorization.

首次同步及新获权项目补齐期间暂无候选，客户端可能只显示空列表；完成后需重新输入查询，当前不会主动刷新已打开的菜单。已有缓存的普通增量同步不阻塞候选，但结果可能短暂陈旧。源码、隔离协议和 macOS/最低 Node 验证已完成，真实 Codex 菜单与其他操作系统验收仍待进行。

Initial synchronization and newly granted Project backfills return no candidates; the client may show an empty list. Enter the query again after completion, as open menus are not refreshed automatically. Ordinary incremental updates retain existing candidates, which can briefly be stale. Source, isolated protocol, and macOS/minimum-Node verification are complete; real Codex menu and other operating-system acceptance remain pending.
