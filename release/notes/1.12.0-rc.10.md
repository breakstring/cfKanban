# cfKanban 1.12.0-rc.10

## 简体中文

相对 RC9，本版修复长时间首次趋势回填的凭据刷新与中断恢复。

- 每次维护控制请求前读取固定 Cloudflare profile 的当前凭据，沿用既有安全 Wrangler 刷新流程，不启动交互登录。
- `operation recover` 只读核对原回填的 fence、已失效租约、提交记录及原 job 进度，不重放历史写入。
- 保留安全的 HTTP status / 平台错误码；缺失用量仍标为未知，按保守上限预留后核对账号用量再继续。
- 继续分离首次回填与小时维护，沿用有限批次、CAS、租约、限速和实际 D1 用量记录。

## English

Compared with RC9, this release fixes credential refresh and interruption recovery for long initial trend backfills.

- Read the frozen Cloudflare profile's current credential before each maintenance request through the existing safe Wrangler flow, without interactive login.
- `operation recover` only reads the original fence, expired lease, commit checkpoint and job progress; it never replays history writes.
- Retain safe HTTP status and numeric provider codes. Missing usage stays unknown with conservative allowance reserved before account-usage verification and another finite plan.
- Keep initial backfill separate from hourly maintenance, with bounded batches, CAS, leases, rate limits and actual D1 usage records.

## 升级提醒 / Upgrade notes

schema 仍为 30，API 仍为 0.1.0，无新增 migration。结果不确定的 RC9 回填需在部署仍匹配原 receipt 时，使用新版本地 CLI 先完成原 operation 的只读恢复，再升级或启动下一轮。原失败日志和 receipt 不改写。

Schema remains 30 and API remains 0.1.0, with no new migration. Recover an unknown RC9 backfill through the updated local CLI while the deployment still matches its original receipt, before upgrading or starting another run. Original failure logs and receipts remain intact.

schema 30 首次安装仍暂不支持；首次安装使用 stable，默认 stable 渠道不变。

First installation of schema 30 remains temporarily unsupported; use stable for new installations. The default stable channel is unchanged.

范围与验收 / Scope and validation: [CFK-730](https://cfkanban.dev/app/issues/CFK-730).
