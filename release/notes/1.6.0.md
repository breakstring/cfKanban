# cfKanban 1.6.0

## 简体中文

相对正式版 `1.5.0`，本版汇总实例通知、历史查阅、发行说明和网页活动续期的改善，方便协作与实例维护。

- **实例通知**：Owner 可发布、撤回公告；用户可选择接收，在 Web 或 Agent 中查看并逐条确认，历史保留过期和撤回状态。常规提醒检查减少历史增长后的重复读取。[CFK-538](https://cfkanban.dev/app/issues/CFK-538)
- **历史最新在前**：项目活动和管理审计先显示最新记录，按需加载较早历史；Agent 原有正序增量读取保持兼容。[CFK-540](https://cfkanban.dev/app/issues/CFK-540)
- **发行说明更清晰**：中英文先介绍用户与管理员的收益，再提供简短升级提醒和可核对的提交链接，便于判断升级影响。[CFK-541](https://cfkanban.dev/app/issues/CFK-541)
- **持续编辑更顺畅**：真实前台操作可自动续期，每 30 分钟最多一次，续期后最长有效 8 小时、首次登录后最多 7 天。到期后可复制主要文字草稿，重新登录后明确恢复，不自动提交；页脚不再常驻显示期限说明，需要重新登录时再提示。[CFK-529](https://cfkanban.dev/app/issues/CFK-529)

## English

Compared with stable `1.5.0`, this release brings together improvements to instance announcements, history browsing, release notes, and activity-based browser sign-in renewal for collaboration and instance maintenance.

- **Instance announcements**: Owners can publish or withdraw notices. Users choose reception, read and individually confirm notices through Web or Agent, and retain history with expired or withdrawn status. Routine reminder checks reduce repeated reads as history grows. [CFK-538](https://cfkanban.dev/app/issues/CFK-538)
- **Newest history first**: Project activity and management audit show the latest records first and load older history on demand. Existing Agent reads in ascending incremental order remain compatible. [CFK-540](https://cfkanban.dev/app/issues/CFK-540)
- **Clearer release notes**: Matching Chinese and English notes lead with benefits for users and administrators, followed by short upgrade guidance and verifiable commit links, making upgrade impact easier to assess. [CFK-541](https://cfkanban.dev/app/issues/CFK-541)
- **Smoother continuous editing**: Real foreground interactions renew browser sessions at most once every 30 minutes, for up to 8 hours from renewal and no more than 7 days from initial sign-in. After expiry, copy supported text drafts or explicitly restore them after signing in again; nothing is submitted automatically. The footer no longer shows ongoing expiry details; a sign-in prompt appears when needed. [CFK-529](https://cfkanban.dev/app/issues/CFK-529)

## 升级与已知限制 / Upgrade and known limitations

从 `1.5.0` 升级需执行三项兼容迁移，将 schema **14 → 17**，先迁移再部署 Worker；从 `1.6.0-rc.2` 升级为 **17 → 17**，无新增迁移。仍须核对实际 schema 与迁移记录，Worker 回滚不回退 D1。普通安装与更新推荐 stable 渠道；实例升级与 Skill 更新分别执行。[升级指南](https://github.com/breakstring/cfKanban/blob/__CANDIDATE_SHA__/apps/docs/zh-CN/deployment/updates.md)

升级前的旧 Cookie 仍按原 8 小时期限到期，重新登录后使用新规则。文字草稿仅保存在本页内存，刷新或关闭页面会丢失；恢复须为同一 Principal 且具有当前权限，提交结果未确认的草稿仅可复制，请先核对上次结果。Agent 在正常调用时发现通知，不会被后台唤醒。

Upgrading from `1.5.0` requires three compatible migrations, moving schema **14 → 17** before deploying the Worker. Upgrading from `1.6.0-rc.2` keeps schema at **17 → 17**, with no new migrations. Verify the actual schema and migration ledger; Worker rollback does not reverse D1 migrations. Use the stable channel for regular installations and updates. Instance upgrades and Skill updates are separate. [Upgrade guide](https://github.com/breakstring/cfKanban/blob/__CANDIDATE_SHA__/apps/docs/en/deployment/updates.md)

Older pre-upgrade cookies retain their original 8-hour expiry; sign in again to obtain the new rules. Text drafts remain only in this page memory and are lost on refresh or close. Restoration requires the same Principal and current access. Drafts with an unconfirmed submission support copying only; check the previous outcome first. Agents discover notices during ordinary calls and are not awakened in the background.
