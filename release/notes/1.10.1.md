# cfKanban 1.10.1

## 简体中文

相对正式版 `1.10.0`，本版汇集 1.10.1 系列 RC 的项目布局、Cloudflare 设置、日度用量与成本保护改进，让日常协作和实例管理更直接。

- 完整版 Web 与本地工作台压缩项目标题、视图切换和筛选区域，让看板与列表显示更多事项；窄屏保留可操作的筛选和展开入口。
- Owner 使用一份 Cloudflare Token 即可连接配置与统计能力，保存后自动核验并加载数据。统计及五组访问频率集中编辑、预览差异并一次保存；冲突保留草稿，未知结果沿原操作核验。
- 用量页集中显示真实 UTC 当日指标、可选的 7/30/90 日历史与附件占用，明确区分缺日和未知值。附件存储上限在同一区域独立保存，无需 Cloudflare Token。
- Web、MCP 与 Skills 合并重复读取，通知与后台清理减少反复数据库工作；匿名登录、计数及标题搜索增加独立限流与并发保护。
- Agent 与公共 CLI 支持一致的多项配置及原请求查询；公开 `/llms.txt` 集中链接双语手册和安装指南，方便 Agent 查阅当前能力与操作边界。

## English

Compared with stable `1.10.0`, this release brings together the 1.10.1 RC improvements to project layouts, Cloudflare settings, daily usage and cost protection, making collaboration and Instance management more direct.

- Compact project headers, view controls and filters in the full Web UI and local workbench give boards and lists more room for Issues. Narrow screens retain usable filter and expand controls.
- Owners can connect configuration and analytics access with one Cloudflare Token, with automatic verification and data loading after saving. Usage settings and five request limits share a form with a combined change preview and save; conflicts retain drafts, and uncertain results are checked against the original operation.
- The usage page brings together actual UTC daily metrics, optional 7/30/90-day history and attachment consumption, distinguishing missing days and unknown values. Attachment capacity is saved independently in the same area without a Cloudflare Token.
- Web, MCP and Skills coalesce duplicate reads, while notifications and background cleanup reduce repeated database work. Anonymous sign-in, counts and title searches gain separate rate and concurrency protection.
- Agents and the public CLI support equivalent combined configuration and original-request lookup. A public `/llms.txt` entry links bilingual manuals and installation guides so agents can discover current capabilities and operation boundaries.

## 升级与已知限制 / Upgrade and known limitations

从 `1.10.0` 升级需按顺序应用六项向后兼容迁移 **0022–0027**，schema 从 **21** 升至 **27**，API 保持 **0.1.0**。使用本发行的部署工具核对实际 migration ledger/schema、D1 恢复点和线上 Worker 配置，保留既有身份、资源、Secrets、限流及完整 Observability 设置。从已验收的 `1.10.1-rc.11` 转为正式版无新增迁移，本次正式化仅收敛版本和发行说明。

Web 访问频率统一按每分钟编辑；既有 10 秒配置准确显示，仅在主动修改对应限制时改为一分钟，不自动换算。历史和账户汇总须明确开启；用量是 Analytics 观测，限流为最佳努力，均不构成账单或费用封顶。域名变更仍需独立部署计划；新的 WAF、用量阈值及预算通知管理不在此设置流程中，已有规则和旧操作记录保留供核验与受控恢复。

Upgrading from `1.10.0` requires six backward-compatible migrations, **0022–0027**, in order, moving schema **21 → 27** while retaining API **0.1.0**. Use this release's deployment tools to verify the actual migration ledger/schema, D1 restore point and live Worker configuration, preserving existing identities, resources, Secrets, request limits and the complete Observability settings. Promoting validated `1.10.1-rc.11` to stable adds no migrations; this promotion changes only version metadata and release notes.

The Web UI edits request limits per minute. Existing 10-second limits remain accurately displayed and switch to one minute only when explicitly edited, without automatic conversion. History and account totals require opt-in. Usage represents Analytics observations, and rate limiting is best effort; neither is an invoice or spending cap. Domain changes still require a separate deployment plan. New WAF, usage-threshold and budget-notification management are outside this settings workflow; existing rules and historical operation records remain available for verification and controlled recovery.
