# cfKanban 1.12.0-rc.8

## 简体中文

相对 `1.12.0-rc.7`，本 RC 将趋势历史回填与小时维护分开，让已有历史在明确预算内连续补齐。

- 首次回填通过独立维护命令按小批次推进，不再等待每小时触发。
- 每批记录 D1 实际读写量、执行时间和进度，达到预算或出现不确定响应即停止。
- 跨机器租约、Issue 版本检查与原子提交共同防止重复统计，并保留中断读回记录。
- 小时任务只负责日常维护；可恢复历史补齐后，无法验证的旧事件仍保持图表断点。

## English

Compared with `1.12.0-rc.7`, this RC separates initial trend backfill from hourly maintenance so existing history can progress continuously within explicit budgets.

- Run initial backfill in small batches through a separate maintenance command instead of waiting for hourly ticks.
- Record actual D1 reads, writes, duration, and progress per batch; stop at budget limits or uncertain responses.
- Cross-host leases, Issue version checks, and atomic commits prevent duplicate counts and retain interruption readback evidence.
- Hourly tasks handle routine maintenance; unverifiable historical events remain chart gaps after recoverable history is processed.

## 升级提醒 / Upgrade notes

新增兼容迁移 `0030_issue_trend_backfill_maintenance.sql`，schema 29 升至 30，API 兼容版本仍为 0.1.0。首次回填需要实例 Owner 与原 Cloudflare 维护授权，使用已验证的不可变 Service 工件；升级不自动启动回填，也不新增付费资源或修改业务事实。升级前核对 ledger/schema 和恢复点。

Adds the compatible `0030_issue_trend_backfill_maintenance.sql` migration from schema 29 to 30; API compatibility remains 0.1.0. Initial backfill requires the instance Owner and existing Cloudflare maintenance authorization, using the verified immutable Service artifact. Upgrading does not start backfill automatically, add paid resources, or modify business facts. Verify ledger/schema and a restore point before upgrading.
