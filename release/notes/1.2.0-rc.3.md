# cfKanban 1.2.0-rc.3

## 简体中文

本候选版本补齐 Owner 设备的网页管理，并支持已有本地身份的电脑安全接入 Owner。

- Owner 管理页的 Access 提供设备列表、配对请求预览、明确批准和专用撤销。正常 Owner 管理会话即可使用，无需额外 Passkey 确认；服务端继续校验同源、CSRF、实时权限、CAS、幂等与原子审计。
- 当前认证来源和最后一份有效 Owner API Credential 不能被撤销。服务端零 active 时禁止新增；有效 Owner 管理会话配合未撤销凭据记录可批准设备，即使旧 secret 文件已丢失。专用部署外全失恢复和普通 Agent 轮换保持原流程。
- 同实例已有本地凭据时，明确选择切换为 Owner；新 Owner 验证成功后才保存旧身份并切换 current。私有 previous 槽提供验证后的显式恢复，保留两侧凭据，不合并 Principal 或改变原授权。中断时使用原操作恢复。
- 新设备仍通过 Skill 在本地生成并保存长期 secret，网页只处理非秘密配对请求；网页批准后须返回新设备完成验证。

## English

This candidate adds Owner device management to the Web and lets a computer with an existing local identity safely connect as Owner.

- Owner Access includes device listing, public pairing previews, explicit approval and dedicated revocation. A normal Owner admin session is sufficient without additional Passkey confirmation. Same-origin, CSRF, live authorization, CAS, idempotency and atomic audit checks remain enforced.
- The current authentication source and last active Owner API Credential are protected. Approval requires at least one unrevoked API Credential record, not proof that its secret file still exists. A valid Owner admin session can approve even after local file loss. Dedicated out-of-band recovery and normal Agent rotation retain their existing workflows.
- Explicitly replacing an existing local identity verifies the new Owner before preserving the old identity and switching current. A private previous slot supports verified restoration while retaining both credentials, without merging Principals or changing grants. Interrupted transitions resume the original operation.
- The new device's Skill still generates and stores its long-lived secret locally. The browser handles only the public pairing request, and approval must be followed by verification on the new device.

## 升级与验证边界 / Upgrade and verification boundaries

从 `1.2.0-rc.2` 升级无新增 migration，schema 保持 `12`，API 保持 `0.1.0`。从 `1.1.1` 升级仍应用 `0012_owner_devices.sql`。新身份切换/恢复需要新版 Skill，`1.1.1` 和 `1.2.0-rc.2` 不支持；切换未完成时须使用支持该事务的版本恢复。网页设备管理需要更新 Service，更新本地 Skill 不会更新线上服务。

There is no new migration from `1.2.0-rc.2`; schema remains `12` and API remains `0.1.0`. Upgrading from `1.1.1` still applies `0012_owner_devices.sql`. Identity replacement/restoration requires a newer Skill; neither `1.1.1` nor `1.2.0-rc.2` implements it. Resume unfinished transitions with a version supporting that transaction. Web device management requires the updated Service; updating local Skills does not update the live instance.

本预发行版不推进 GitHub Latest 或 canonical stable。574 项隔离测试与桌面/手机端浏览器组件验收通过；真实跨电脑操作和浏览器连接真实 Worker 的完整 E2E 尚未验收。GitHub 发行、线上升级和本机插件更新各自独立读回；更新磁盘上的插件不会自动重载当前任务已加载的技能。

This prerelease does not advance GitHub Latest or the canonical stable pointer. All 574 isolated tests and desktop/mobile browser component checks passed; real cross-computer operations and a full browser-to-Worker E2E flow remain unverified. GitHub publication, live upgrade and local plugin installation require separate readback. Updating a plugin on disk does not reload Skills already loaded in the current task.
