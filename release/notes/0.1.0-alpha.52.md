# cfKanban 0.1.0-alpha.52

## English

- Remove Workspace/Project keys. Create containers using display names; API paths, Web links and Agent scope use stable UUIDs. Names may repeat. Old key-based URLs/API requests are unsupported, and local scope uses schema version 2.
- Improve archive grouping and name-copy feedback; add workspace/project icons and details to distinguish same-name archived objects before permanent deletion.
- Close the Invitation redemption secret-overlap gap for workspace names, including concurrent changes. Rejected redemptions leave no identity, Grant or secret snapshot behind.
- Apply migration `0003_container_uuid.sql` to schema 3. Preserve business data, UUIDs, permissions, credentials and Issue numbering; convert Launch/Session targets, remove obsolete operation snapshots, and upgrade checksum ledger constraints while preserving its history.
- This is an incompatible development migration. The exact upgrade plan must explicitly allow the change and include a verified D1 restore point. Service may be unavailable between migration and the compatible Worker deployment. Do not roll back to an older Worker after migration; no automatic D1 restore occurs.

## 简体中文

- 移除工作区/项目 key，创建只需名称；API、Web 链接及 Agent scope 使用稳定 UUID。名称允许重复，不兼容旧 key 地址或请求，本地 scope 使用 schema version 2。
- 优化归档分组与名称复制反馈，增加工作区/项目图标和对象详情，永久删除前可准确区分同名对象。
- 修复邀请兑换中工作区名称的秘密值重叠校验，覆盖并发改名；拒绝时不创建身份或授权，也不遗留秘密快照。
- 通过 `0003_container_uuid.sql` 升级至 schema 3，保留业务数据、UUID、权限、凭据和事项编号，转换 Launch/Session 目标，清除旧操作快照，并升级 checksum 账本约束、保留历史记录。
- 本版包含开发阶段不兼容迁移，升级计划须明确允许该变化并包含已验证的 D1 恢复点。迁移到兼容 Worker 发布之间可能中断服务；迁移后禁止回滚旧 Worker，不自动执行 D1 restore。
