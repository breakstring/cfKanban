# cfKanban 1.10.1-rc.9

## 简体中文

相对 `1.10.1-rc.8`，本 RC 修复用量与访问设置的保存问题，并简化访问频率和附件存储配置。

- 打开设置页时不再将历史失败操作显示为当前保存失败；待核验的操作仍保留原请求和恢复入口。
- 修复 Cloudflare 配置写入格式，并兼容其返回的空 placement 配置；保存失败后的能力复查帮助继续修改。
- Web 统一按每分钟编辑访问频率，省去时间窗口选择；旧 10 秒配置准确显示，仅在主动修改对应频率时切换到一分钟。
- 附件存储上限集中放在用量与访问设置区域，保留独立保存和冲突保护；用量统计区域展示只读容量与占用。

## English

Compared with `1.10.1-rc.8`, this RC fixes saving usage and access settings and simplifies request limits and attachment storage configuration.

- Opening settings no longer presents a historical failed operation as a new save failure. Operations awaiting verification retain their original request and recovery controls.
- Cloudflare settings writes use the correct format and accommodate empty placement configuration returned by Cloudflare. Capability checks after failed saves help users continue editing.
- The Web UI edits request limits per minute without a window selector. Existing 10-second limits remain accurately displayed and switch to one minute only when that limit is explicitly edited.
- Attachment capacity is configured alongside usage and access settings, with independent saving and conflict protection. Usage statistics show capacity and consumption as read-only information.

## 升级与已知限制 / Upgrade and known limitations

相对 `1.10.1-rc.8` 无新增 migration，schema 保持 **27**，API 保持 **0.1.0**；升级仍需核对真实 ledger/schema。附件容量是应用设置，与 Cloudflare 配置分别保存。API 继续兼容 10 秒和 60 秒窗口；旧配置不会自动换算。

No migration is added relative to `1.10.1-rc.8`: schema remains **27** and API remains **0.1.0**; the actual ledger and schema must still be checked during upgrade. Attachment capacity is an application setting saved separately from Cloudflare configuration. The API retains 10-second and 60-second windows; existing limits are not automatically converted.
