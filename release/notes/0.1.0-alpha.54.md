# cfKanban 0.1.0-alpha.54

## English

- Fix existing-instance migration execution: submit each verified public migration as one bounded D1 query, preserving transaction-scoped foreign-key deferral. File ingestion can reset that pragma before the migration finishes.
- Bind single-query execution and the 24 KiB UTF-8 limit to the upgrade plan and journal; reject old execution plans, oversized SQL, splitting, and file fallback. Owner bootstrap and checksum SQL keep their existing file paths.
- Keep the UUID migration SQL digest unchanged. Isolated remote D1 reproduction verified the complete migration twice and full rollback on an injected final-statement failure; the temporary diagnostic database was removed.
- Includes alpha.52/53 UUID container and migration-readback changes. Upgrading schema 2 to 3 preserves business records, identities, credentials, grants, and Issue numbers, but removes old idempotency/operation snapshots and key-based addresses. Record a restore point first; an old schema-2 Worker cannot be used after migration. D1 restore is never automatic.

## 简体中文

- 修复已有实例的 migration 执行：每条已验证公开 SQL 通过一次有界 D1 query 提交，保留事务内的外键延迟检查。文件 ingestion 可能在迁移完成前重置该 PRAGMA。
- 执行方式与 24 KiB UTF-8 限额绑定 upgrade plan 和 journal；拒绝旧执行计划、超限 SQL、拆分及 file fallback。Owner bootstrap 与 checksum SQL 保留原有文件路径。
- UUID migration SQL 摘要不变。隔离远端 D1 已验证两次完整迁移及末尾语句故障时整批回滚，临时诊断数据库已删除。
- 包含 alpha.52/53 的 UUID 容器和迁移读回修复。schema 2 升至 3 保留业务数据、身份、凭据、授权和 Issue 编号，但清除旧幂等/操作快照，移除 key 地址。升级前记录恢复点；迁移后不能回退 schema 2 Worker，不自动执行 D1 restore。
