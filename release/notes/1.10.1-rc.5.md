# cfKanban 1.10.1-rc.5

## 简体中文

相对已公开的 `1.10.1-rc.4`，本 RC 简化管理设置，并让 Cloudflare Token 的保存结果与故障原因更清楚。

- 统一使用「保存 Token」，连接成功后收为小卡片；各项功能以实际检查结果显示，展开或悬停可查看权限与范围说明。
- 区分明确保存失败、结果待确认和保存后功能检查失败，提供失败步骤、HTTP 状态和请求 ID；结果待确认时核对原请求，避免重复提交，可选功能由用户主动检查。
- 访问频率限制移至「用量与限额」，说明不可修改的原因，并在确认保存前展示修改前后的值。
- 首页实例说明打开即显示生效内容，修改后直接保存，无需额外点击「读取最新设置」。

## English

Compared with published `1.10.1-rc.4`, this RC simplifies administration settings and makes Cloudflare Token save results and failures clearer.

- Use one Save Token action and a compact card after connecting. Function statuses reflect actual checks, with expandable or hoverable permission and scope details.
- Distinguish rejected saves, unconfirmed results and post-save function check failures, with the failed step, HTTP status and request ID. Check the original request before any retry, and check optional functions only when requested.
- Manage request rate limits under Usage & limits, with explanations when editing is unavailable and a before-and-after comparison before confirming the save.
- See the active homepage instance notice when opening the page and save edits directly, without a separate Read latest settings action.

## 升级与已知限制 / Upgrade and known limitations

从 `1.10.1-rc.4` 升级无新增 migration，schema 保持 **26**，API 保持 **0.1.0**；仍须核对实际 ledger/schema 和线上配置。Owner 仍自行输入 Token，真实权限与保存结果以线上响应及读回为准；此前保存失败的具体原因无法从旧提示反推。

Upgrading from `1.10.1-rc.4` adds no migrations and keeps schema **26** and API **0.1.0**; the actual ledger/schema and live configuration must still be checked. Owners still enter their Token themselves. Live responses and readback determine its permissions and save result; the exact cause of an earlier failure cannot be reconstructed from the old message.
