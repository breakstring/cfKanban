# cfKanban 1.12.0-rc.9

## 简体中文

相对 `1.12.0-rc.8`，本 RC 修复趋势回填迁移在远端 D1 查询入口的兼容问题。

- 保留已发布的迁移文件与摘要，通过范围固定的 CASE 括号处理兼容远端解析器。
- 升级计划明确绑定原文及实际执行 SQL 的摘要，旧计划不会隐式采用兼容处理。
- 继续使用单次查询升级、schema/ledger 读回和不确定响应停止机制。
- 大型部署工件上传可等待最多 15 分钟，超时后先读回，避免两分钟默认等待误中断。

## English

Compared with `1.12.0-rc.8`, this RC fixes compatibility of the trend backfill migration with the remote D1 query endpoint.

- Preserve published migration bytes and hashes while applying a narrowly scoped CASE-parenthesis compatibility transformation.
- Bind both source and executed SQL hashes to the upgrade plan; existing plans never adopt the transformation implicitly.
- Retain single-query upgrades, schema/ledger readback, and stops on uncertain responses.
- Allow up to 15 minutes for large deployment uploads, with readback required after timeout.

## 升级提醒 / Upgrade notes

schema 仍为 30，API 兼容版本仍为 0.1.0。schema 29 升级需使用本版本生成的新计划；RC8 的失败计划不能直接替换摘要续做。首次历史回填与小时维护的分离沿用 RC8，升级后仍需单独执行有界回填。

本 RC 暂用于现有实例升级，不支持 schema 30 首次安装；新装计划及旧计划的云端写入会提前停止。首次安装继续使用正式 stable 版本，默认 stable 渠道不变。

Schema remains 30 and API compatibility remains 0.1.0. Upgrades from schema 29 require a new plan generated by this release; do not replace hashes in a failed RC8 plan. Initial history backfill remains separate from hourly maintenance and must be run explicitly after upgrading.

This RC supports existing-instance upgrades and temporarily blocks first installation of schema 30, including cloud writes under an older initial plan. New installations should use the stable release; the default stable channel is unchanged.

范围与验收 / Scope and validation: [CFK-730](https://cfkanban.dev/app/issues/CFK-730).
