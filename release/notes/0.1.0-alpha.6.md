# cfKanban 0.1.0-alpha.6

Testing prerelease / 测试发行版

## English

This testing prerelease fixes the D1 creation command mismatch found during the first authorized `0.1.0-alpha.5` cloud rehearsal. Wrangler `4.127.1` supports JSON output for `d1 list`, but not for `d1 create`; the unsupported flag caused the command to stop before Cloudflare created any resource.

Changes:

- invokes `wrangler d1 create <name>` without the unsupported `--json` flag;
- fixes every allowlisted deployment subprocess to the Cloudflare account ID frozen in the authorized plan;
- adds `runtime d1-resource-readback`, which returns only an exact target name and verified database UUID, or `absent`, without exposing other account databases;
- requires exact-name D1 readback before and after creation and never parses human-oriented creation output as authoritative state;
- stops on a failed create followed by a present resource because ownership would be ambiguous;
- retains the Tool Runtime reuse and deterministic least-scope Cloudflare login contracts from the previous testing releases.

The failed `0.1.0-alpha.5` rehearsal created no Worker or D1 and ran no migration or Owner bootstrap. Its local journal remains as audit evidence.

Important limits:

- this is not the stable channel and must be selected explicitly;
- use a non-production Cloudflare account and review each exact local, authentication, and deployment plan before approval;
- resource cleanup is separate and is never performed automatically.

Install the tagged plugin:

```text
codex plugin marketplace add https://github.com/breakstring/cfKanban.git --ref 0.1.0-alpha.6
codex plugin add cfkanban-agent-skills@cfkanban
```

Start a new Codex task and say:

```text
Use $cfkanban-deploy to deploy cfKanban for me.
```

## 简体中文

这个测试发行版修正了首次授权执行 `0.1.0-alpha.5` 云端演练时发现的 D1 创建命令不匹配。Wrangler `4.127.1` 的 `d1 list` 支持 JSON 输出，但 `d1 create` 不支持；这个无效参数使命令在 Cloudflare 创建任何资源前就停止了。

变更：

- 调用 `wrangler d1 create <name>` 时不再携带不受支持的 `--json`；
- 所有 allowlisted 部署子进程都显式固定到已授权计划中的 Cloudflare account ID；
- 新增 `runtime d1-resource-readback`，只返回准确目标名称及已验证的数据库 UUID，或 `absent`，不暴露账户中的其他数据库；
- D1 创建前后都必须执行准确名称读回，绝不把面向人类的创建输出当作权威状态；
- 如果创建失败但读回发现资源存在，因为归属不明确而停止；
- 保留此前测试发行版的 Tool Runtime 复用与确定性最小权限 Cloudflare 登录合同。

失败的 `0.1.0-alpha.5` 演练没有创建 Worker 或 D1，也没有执行 migration 或 Owner bootstrap；其本地 journal 保留为审计证据。

重要限制：

- 这不是稳定发行通道，必须由用户明确选择；
- 请使用非生产 Cloudflare 账户，并分别核对准确的本地、认证与部署计划后再授权；
- 资源清理是独立操作，绝不会自动执行。

安装带 tag 的 plugin：

```text
codex plugin marketplace add https://github.com/breakstring/cfKanban.git --ref 0.1.0-alpha.6
codex plugin add cfkanban-agent-skills@cfkanban
```

新建 Codex 任务后只需要说：

```text
请使用 $cfkanban-deploy 为我部署一套 cfKanban。
```
