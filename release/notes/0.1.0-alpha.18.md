# cfKanban 0.1.0-alpha.18

Testing prerelease / 测试发行版

## English

This testing prerelease aligns the first-party Web UI with the authorization and target already fixed by the Service. It closes cases where an Owner opened a Project-scoped Session but still saw instance controls, a Passkey Session displayed a registration action that the Service would reject, or an admin Browser Launch always landed on Overview.

Changes:

- restores the exact requested Owner admin section from the server-provided Browser Launch entry path;
- uses the server-provided Passkey exchange entry path after strict same-origin app-path validation;
- exposes Owner navigation and mounts the Owner control plane only for an Owner Session with instance scope;
- shows Passkey registration only for Credential-source Sessions in browsers with WebAuthn support;
- enables Relation creation only when both distinct Issue endpoints are writable and belong to the same Workspace;
- renders deleted Issue recovery from tombstone `allowed_actions`, `restorable`, parent state, and unavailability details;
- presents public Passkey authentication 401 responses as one Passkey failure instead of a stale Session message;
- treats blocked or quota-limited locale storage as best effort, without preventing application startup or in-memory locale changes;
- strengthens Browser Launch navigation against external, fragment, and non-app destinations;
- adds authorization, source, Relation, entry-path, storage-failure, and all-admin-section regression coverage.

The Service and Web bundles change in this release. Existing alpha.17 Skills remain API-compatible, but deployed instances must be upgraded to receive these Web corrections. The D1 schema stays at version 1 and this release adds no migration.

Important limits:

- this is not the stable channel and must be selected explicitly;
- alpha.18 does not complete the remaining pagination and browser-concurrency release-candidate work;
- Passkey availability still depends on the browser, HTTPS origin, and a registered authenticator;
- host or operating-system permission prompts remain independent of cfKanban's application-level authorization.

Install the tagged plugin:

```text
codex plugin marketplace add https://github.com/breakstring/cfKanban.git --ref 0.1.0-alpha.18
codex plugin add cfkanban-agent-skills@cfkanban
```

Start a new Codex task and say:

```text
Use $cfkanban-admin to create my first cfKanban board.
```

## 简体中文

这次测试发行让第一方 Web UI 与 Service 已固定的权限范围和目标保持一致。它收敛了几类偏差：Owner 使用 Project scope Session 时仍看到实例控制面、Passkey Session 显示必然被 Service 拒绝的登记入口，以及 admin Browser Launch 总是落到 Overview。

变更：

- 根据服务端 Browser Launch `entry_path` 恢复准确的 Owner admin 分区；
- Passkey exchange 后只使用经过严格同源 app 路径校验的服务端 `entry_path`；
- 只有同时具备 Owner 身份和 instance scope 的 Session 才显示 Owner 导航并挂载控制面；
- 只有 Credential-source Session 且浏览器支持 WebAuthn 时才显示 Passkey 登记；
- 只有两个不同 Issue 位于同一 Workspace 且两端都可写时，才允许创建 Relation；
- deleted Issue 的恢复展示改为使用 tombstone 的 `allowed_actions`、`restorable`、父容器状态和不可用原因；
- public Passkey 认证返回 401 时统一显示 Passkey failure，不再误报旧 Session 已结束；
- localStorage 被禁用或达到 quota 时按 best-effort 处理，不阻断应用启动和内存中的语言切换；
- Browser Launch 跳转拒绝外部、fragment 和非 app 目标；
- 增加权限、Session 来源、Relation、入口路径、存储失败及全部 admin 分区的回归覆盖。

本发行同时改变 Service 与 Web bundle。alpha.17 Skills 仍与 API 兼容，但既有部署实例需要升级才能获得这些 Web 修正。D1 schema 仍为版本 1，本次没有新增 migration。

重要限制：

- 这不是 stable channel，必须由用户明确选择；
- alpha.18 尚未完成剩余的分页和浏览器并发 release-candidate 工作；
- Passkey 是否可用仍取决于浏览器、HTTPS origin 和已经登记的 authenticator；
- Agent 宿主或操作系统自己的权限提示仍独立于 cfKanban 应用层授权。

