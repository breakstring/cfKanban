# cfKanban 1.3.0-rc.1

## 简体中文

本候选版基于 `1.2.0`，补齐 Web 与 Agent 的常用协作能力，并优化看板和管理页面的信息密度。

- Web 提供跨项目工作清单、我的任务及待领取/需重指派队列，补齐工作区和项目分页、项目活动、负责人筛选及结构化交接摘要；完成记录的验证、产物和后续事项保留结构化内容，包括空摘要的历史记录。
- 支持创建包含多个项目授权的邀请。已登录参与者可在 Web 明确确认后以当前 Principal 接受普通 `project_grant` 邀请，保留同源、CSRF 和实时权限检查，不改变当前 Session scope 或到期时间；不包含新用户、身份恢复或 Owner 设备邀请。响应不确定及会话暂时不可读时保留原请求与幂等键供核实恢复。
- Bearer 调用方可以查询并精确撤销本人的 Passkey，保留 CAS、幂等重放、原子审计及来源 Session 撤销。Passkey 登记仍由浏览器完成。
- Owner 设备名称可通过 Web 和 Agent 修改；名称变更不轮换 Credential、不改变设备或 Principal 身份。
- 看板卡片合并信息行、减少内边距，常见卡片高度约为此前一半；保留优先级快捷修改、拖拽/菜单状态操作、重指派提示、标签摘要和完整详情入口。工作区管理的项目名称与操作按钮垂直居中，长名称在窄屏完整换行。
- 修复后续分页工作区改名遇到版本冲突时的精确读回，并保留编辑草稿与已加载分页。

## English

This release candidate builds on `1.2.0`, adds everyday collaboration capabilities across Web and Agent, and improves board and management-page density.

- Web adds cross-project work lists, assigned work, unassigned/reassignment queues, paginated workspace/project navigation, project activity, assignee filters and structured handoff context. Completion evidence, artifacts and follow-ups remain structured, including records with an empty summary.
- Invitations can grant access to multiple projects. An authenticated participant can explicitly accept an ordinary `project_grant` invitation as the current Principal in Web, with same-origin, CSRF and live authorization checks. The current Session scope and expiry remain unchanged. New identities, recovery and Owner-device invitations are excluded. Uncertain responses and temporary session-read failures retain the original request and idempotency key for verification.
- Bearer callers can list and precisely revoke their own Passkeys with CAS, idempotent replay, atomic audit and source-session revocation. Registration remains a browser operation.
- Owner device names can be changed from Web and Agent without rotating credentials or changing device or Principal identity.
- Compact board cards share metadata rows and reduce padding; common cards are approximately half their previous height. Priority shortcuts, drag/menu status changes, reassignment markers, label summaries and full detail access remain available. Workspace project rows center names and actions, with complete name wrapping on narrow screens.
- Renaming a workspace on a later page now reads back that exact workspace on a version conflict while preserving the draft and loaded pages.

## 升级与验证 / Upgrade and verification

从 `1.2.0` 升级无新增 migration；schema 保持 `12`，API 保持 `0.1.0`。保留现有实例、资源、Owner、Credential、授权和业务数据。新增认证入口需要本候选版 Service；本机 Skill/插件更新与实例升级分别执行，不能互相替代。Cookie 邀请仅面向非 Owner 参与者，固定 Session 范围仍需覆盖全部邀请目标；Bearer Passkey 撤销必须提供当前版本和幂等键；Owner 设备改名使用 `/me.version`。

Upgrading from `1.2.0` introduces no migration; schema remains `12` and API remains `0.1.0`. Existing instance resources, Owners, credentials, grants and business data are preserved. New authentication entry points require this Service release; Skill/plugin installation and instance deployment are separate operations. Cookie invitations are for non-Owner participants, and fixed Session scope must cover every invitation target. Bearer Passkey revocation requires the current version and an idempotency key; Owner device renaming uses `/me.version`.

客户端应读取完成记录新增的 `completion` 结构化投影；完成评论的 `body` 统一为摘要，空摘要为 `""`，不再依赖解析内部 JSON 正文。新增 `rename_owner_device` action，客户端继续容忍新增响应字段与 action。

Clients should use the added structured `completion` projection. Completion-comment `body` consistently contains the summary, or `""` when empty; clients must not depend on parsing internal JSON from that body. The `rename_owner_device` action is also added; clients should continue tolerating added response fields and actions.

已完成本地隔离的接口/权限/幂等回归，以及 Chrome 桌面和窄屏的卡片、分页冲突、邀请恢复、交接内容和项目管理交互验证；完整源码与发行检查结果记录在发版 Issue。已知限制：英文窄屏的原有看板页头可能被操作区挤压换行；本轮未验证 Safari/Firefox，不将本地测试视为全部线上或跨设备验收。RC 不推进 GitHub Latest，canonical stable 继续指向 `1.2.0`。插件磁盘更新不证明当前对话已重新加载。

Local isolated API, authorization and idempotency regressions and Chrome desktop/mobile interaction checks cover cards, paginated conflicts, invitation recovery, handoff content and project management. Full source/release verification results are recorded in the release Issue. Known limits: the existing English narrow-screen board header can wrap excessively beside its actions; Safari/Firefox were not tested. Local checks do not establish all live or cross-device acceptance. This prerelease does not advance GitHub Latest; canonical stable remains `1.2.0`. Updating plugin files does not prove that the current conversation has reloaded them.
