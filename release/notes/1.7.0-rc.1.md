# cfKanban 1.7.0-rc.1

## 简体中文

相对正式版 `1.6.0`，本 RC 汇总其后的登录提示、项目关联、技能更新选择和数据库读取改善，方便日常协作与实例维护。

- **重新登录提示更清楚**：网页会话结束时直接提示重新登录后继续访问，中英文表达一致。
- **项目关联跟随工作树**：从仓库子目录或 linked worktree 使用 Agent 时，可识别各自工作树根目录并复用项目关联；接受建议后才保存，保留既有关联。
- **技能更新承接明确目标**：文字要求更新可沿用当前会话已明确选择的准确 RC；未指定目标时仍使用最新正式版，分别核对本次安装副本与长期稳定更新来源。
- **减少重复数据库读取**：优化成员、邀请及协作列表的分页和摘要查询，减少代表性场景下的重复读取，保留实时权限、完整历史和精确统计语义。

## English

Compared with stable `1.6.0`, this RC includes subsequent improvements to sign-in prompts, project associations, Skill update selection, and database reads for everyday collaboration and instance maintenance.

- **Clearer sign-in prompts**: When a browser session ends, matching English and Chinese messages ask users to sign in again to continue.
- **Project associations follow the worktree**: Agents used from repository subdirectories or linked worktrees detect the corresponding worktree root and reuse its project associations. Associations are saved only after acceptance, preserving existing targets.
- **Skill updates retain an explicit target**: A text request to update can reuse the exact RC already selected in the current conversation. Without an explicit target, updates still select the latest stable release; the installed copy and long-term stable update source are checked separately.
- **Fewer repeated database reads**: Member, invitation, and collaboration list pagination and summary queries reduce repeated reads in representative cases while preserving live permissions, complete history, and exact statistics.

## 升级与已知限制 / Upgrade and known limitations

从 `1.6.0` 升级需先执行 `0018_read_query_indexes.sql`，将 schema **17 → 18**，再部署 Worker；迁移新增 11 个索引，不改变业务数据结构，API 保持 `0.1.0`。须核对真实迁移记录与 schema，评估既有数据的索引构建成本和持续写入放大；Worker 回滚不回退 D1。普通安装仍推荐 stable，实例升级与 Skill 更新分别执行。

读取成本证据来自本地隔离数据，不能证明线上计费降幅；稀疏匹配、空页和精确计数仍可能随历史或匹配规模增长。[读取与索引成本记录 / Read and index cost evidence](https://github.com/breakstring/cfKanban/blob/9620fb2962c8374b8830a2a0596dc7ce6cd8e156/docs/research/d1-read-optimization-2026-10-02.md)。升级后选择 RC 的 `release discover` 调用需显式传入 `selectionMode: exact_version` 和准确 `version`；刷新固定 tag 不会自动取得最新正式版。当前聊天是否加载新技能须单独核对。

Upgrading from `1.6.0` requires applying `0018_read_query_indexes.sql` before deploying the Worker, moving schema **17 → 18**. The migration adds 11 indexes without changing business data structures; the API remains `0.1.0`. Verify the actual migration ledger and schema, and assess index construction costs for existing data and ongoing write amplification. Worker rollback does not reverse D1 migrations. Regular installations should still use stable; instance upgrades and Skill updates are separate.

Read-cost evidence comes from isolated local data and does not establish lower live billing. Sparse matches, empty pages, and exact counts can still grow with history or matching data. See the [read and index cost evidence](https://github.com/breakstring/cfKanban/blob/9620fb2962c8374b8830a2a0596dc7ce6cd8e156/docs/research/d1-read-optimization-2026-10-02.md). After updating, `release discover` requests selecting an RC must explicitly pass `selectionMode: exact_version` and an exact `version`. Refreshing a fixed tag does not obtain the latest stable release. Loading the new Skills in the current chat requires separate verification.
