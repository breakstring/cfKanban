# cfKanban 0.1.0-alpha.8

Testing prerelease / 测试发行版

## English

This testing prerelease fixes an authentication-context discovery gap found during the `0.1.0-alpha.7` deployment rehearsal. A fresh Agent task could verify a profile/account pair once it already knew both values, but it could not independently recover an existing Wrangler profile and its Cloudflare account. That could lead it to propose an unnecessary second login.

Changes:

- adds `runtime resolve-cloudflare-auth` before every login proposal;
- discovers effective environment authentication or existing Wrangler profiles and their Cloudflare account memberships;
- automatically reuses exactly one verified mapping, presents multiple mappings for explicit user selection, and stops when a listed profile or inventory cannot be resolved safely;
- keeps Wrangler tokens inside the bounded helper process and returns no token, user email, directory binding, Cloudflare resource inventory, or raw Wrangler output;
- still requires `runtime wrangler-account-readback` for the selected exact profile/account before any deployment plan;
- updates the English and Simplified Chinese Skill guides, bootstrap documents, and user-facing installation documentation.

The `0.1.0-alpha.7` rehearsal was stopped at the Owner display-name question. It did not create a deployment plan, Worker, D1 database, migration, Owner, or other Cloudflare resource.

Important limits:

- this is not the stable channel and must be selected explicitly;
- use a non-production Cloudflare account and review each exact local, authentication, and deployment plan before approval;
- resource cleanup is separate and is never performed automatically.

Install the tagged plugin:

```text
codex plugin marketplace add https://github.com/breakstring/cfKanban.git --ref 0.1.0-alpha.8
codex plugin add cfkanban-agent-skills@cfkanban
```

Start a new Codex task and say:

```text
Use $cfkanban-deploy to deploy cfKanban for me.
```

## 简体中文

这个测试发行版修复了 `0.1.0-alpha.7` 部署演练发现的认证上下文发现缺口。新 Agent 任务只要预先知道 profile/account 两个值，就能验证它们；但它无法自行找回已有 Wrangler profile 及其 Cloudflare account，因此可能错误地提出第二次登录。

变更：

- 在每次提出登录前新增 `runtime resolve-cloudflare-auth`；
- 发现当前生效的环境认证，或已有 Wrangler profiles 及其 Cloudflare account memberships；
- 只有一个已验证映射时自动复用；存在多个映射时交给用户明确选择；profile 或 inventory 无法安全解析时停止；
- Wrangler token 始终留在范围受控的 helper 进程内部，不返回 token、用户邮箱、目录绑定、Cloudflare 资源清单或 Wrangler 原始输出；
- 生成任何部署计划前，仍必须使用 `runtime wrangler-account-readback` 对所选准确 profile/account 做最终读回；
- 同步更新 English/简体中文 Skill 指南、bootstrap 文档和面向用户的安装说明。

`0.1.0-alpha.7` 演练停在 Owner display name 询问处；没有生成部署计划，也没有创建 Worker、D1 database、migration、Owner 或其他 Cloudflare 资源。

重要限制：

- 这不是稳定发行通道，必须由用户明确选择；
- 请使用非生产 Cloudflare 账户，并分别核对准确的本地、认证与部署计划后再授权；
- 资源清理是独立操作，绝不会自动执行。

安装带 tag 的 plugin：

```text
codex plugin marketplace add https://github.com/breakstring/cfKanban.git --ref 0.1.0-alpha.8
codex plugin add cfkanban-agent-skills@cfkanban
```

新建 Codex 任务后只需要说：

```text
请使用 $cfkanban-deploy 为我部署一套 cfKanban。
```
