# cfKanban 1.12.0

## 简体中文

相对正式版 `1.11.0`，本正式版增加里程碑与事项趋势，并完善 Agent 发现、历史回填和部署体验。

- 项目可按需设置里程碑；事项可以不归属里程碑，也可归属一个里程碑，在详情、编辑页、本地工作台、CLI 和 Skills 中一致维护。
- 项目提供未完成存量、每日新增与完成趋势及里程碑完成进度；工作区管理员在设置的趋势标签中查看全部未归档项目，并可维护工作区描述。视图切换、搜索和筛选布局更统一。
- 首次历史回填独立于小时维护，以有界批次连续推进并记录实际 D1 用量，使用租约与并发校验避免重复提交，支持长任务凭据刷新和只读中断核查。
- 补齐公开 API 与 Skills 发现、robots 内容信号、公开页面 Markdown 协商及现有凭据的 `/auth.md` 获取与鉴权指引。
- 首次部署可用 schema 30/31 的完整已验证迁移计划，通过独立执行副本处理固定 SQL 兼容问题；写入前检查源与执行摘要，保留已发行工件和原始数据库校验记录。

## English

Compared with stable `1.11.0`, this release adds milestones and Issue trends, and improves agent discovery, historical backfill and deployment.

- Projects can optionally define milestones. An Issue may have no milestone or belong to one, with consistent management in detail and edit pages, the local workbench, CLI and Skills.
- Projects provide unfinished-stock, daily created and completed trends, and milestone progress. Workspace administrators see all unarchived Projects in a settings trend tab and can maintain Workspace descriptions. View switches, search and filters share a more consistent layout.
- Initial history backfill runs separately from hourly maintenance in bounded consecutive batches, records actual D1 usage, and uses leases and concurrency checks to prevent duplicate commits. Long-running jobs support credential refresh and read-only interruption reconciliation.
- Public API and Skill discovery, robots content signals, Markdown negotiation for public pages, and `/auth.md` guidance for obtaining and using existing credentials are available.
- First deployment supports schemas 30 and 31 through a complete verified migration plan and separate execution copies for a fixed SQL compatibility issue. Every write checks source and execution digests while preserving published artifacts and original database checksum records.

## 升级与已知限制 / Upgrade and known limitations

从 `1.11.0` 升级前先更新本地 Skills/CLI，再执行迁移 `0028`–`0031`，schema 27 → 31；从 RC11/RC12 升级无新增迁移。旧实例升级不自动启动历史回填；可恢复历史通过独立维护计划补齐，使用 schema 31 升级回执与匹配的不可变 Service 工件。API 仍为 0.1.0，升级前核对真实 ledger/schema 并保留既有身份、资源、配置与数据。首次部署 schema 30/31 必须生成本版完整新计划，旧初装计划不能续做；迁移结果不明时停止，不自动重试。首次部署已完成隔离验收，未额外在 Cloudflare 创建完整新实例。

Update local Skills/CLI before upgrading from `1.11.0`, then apply migrations `0028`–`0031`, moving schema 27 to 31. Upgrading from RC11 or RC12 adds no migrations. Recoverable history on upgraded Instances requires a separate maintenance plan; upgrading does not start backfill automatically. Use the schema 31 upgrade receipt and matching immutable Service artifact. API remains 0.1.0; verify the actual ledger and schema and preserve existing identities, resources, configuration and data. First deployment for schemas 30 and 31 requires a complete new plan from this release; legacy initial plans cannot resume. Unknown migration outcomes stop without automatic retries. First deployment passed isolated validation; no additional complete new Instance was created on Cloudflare.

工作区趋势仅限实例 Owner 和对应工作区管理员，超过 100 个未归档项目时明确拒绝。历史覆盖受保留事件限制，图表按 UTC 日统计；里程碑显示范围与已完成存量，不含理想燃尽线。`/auth.md` 不引入 OAuth 或匿名注册，Cloudflare 完整注册发现仍留作后续工作。

Workspace trends is restricted to the Instance Owner and that Workspace's administrators, and explicitly rejects more than 100 unarchived Projects. Historical coverage depends on retained events; charts use UTC days. Milestone charts show scope and completed stock without an ideal burndown line. `/auth.md` does not add OAuth or anonymous registration; complete Cloudflare registration discovery remains future work.
