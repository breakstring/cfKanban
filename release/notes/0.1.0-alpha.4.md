# cfKanban 0.1.0-alpha.4

Testing prerelease / 测试发行版

## English

This testing prerelease fixes the Cloudflare authentication step discovered during the `0.1.0-alpha.3` clean deployment rehearsal. The Skill now inspects, plans, executes, and reads back authentication as an explicit boundary before it creates a deployment plan.

Changes:

- uses `wrangler auth create <name>` for a named local profile instead of the invalid `wrangler login --profile` combination;
- requests only `account:read`, `user:read`, `workers_scripts:write`, and `d1:write`, passed as separate process arguments;
- exposes that enabling Wrangler keyring storage changes a global preference for every Wrangler profile owned by the current operating-system user;
- uses the default Wrangler profile for browser or device login when named profiles are unsuitable; device authorization never pretends to create a named profile;
- binds every login action to one Agent task and frozen plan digest, enforces action order, disables Wrangler disk logs for the auth commands, and returns no raw OAuth output;
- keeps Cloudflare login separate from the later deployment plan: login creates no Worker or D1 resource;
- continues to accept Node.js `>=22.12.0 <27` and pins Wrangler to `4.127.1`.

Important limits:

- this is not the stable channel and must be selected explicitly;
- named Wrangler profiles are still an experimental Wrangler capability;
- use a non-production Cloudflare account and review the exact authentication and deployment plans before approving either boundary;
- resource cleanup is separate and is never performed automatically.

Install the tagged plugin:

```text
codex plugin marketplace add https://github.com/breakstring/cfKanban.git --ref 0.1.0-alpha.4
codex plugin add cfkanban-agent-skills@cfkanban
```

Start a new Codex task and say:

```text
Use $cfkanban-deploy to deploy cfKanban for me.
```

## 简体中文

这个测试发行版修正了 `0.1.0-alpha.3` 干净环境部署演练中发现的 Cloudflare 认证步骤缺陷。Skill 现在会先明确完成认证检查、计划、执行和读回，再生成真正的部署计划。

变更：

- named local profile 使用 `wrangler auth create <name>`，不再使用无效的 `wrangler login --profile` 组合；
- 只请求 `account:read`、`user:read`、`workers_scripts:write` 和 `d1:write`，并把它们作为彼此独立的进程参数传递；
- 明确说明启用 Wrangler keyring 会改变当前操作系统用户全部 Wrangler profiles 的全局偏好；
- named profile 不适用时，browser 或 device 登录使用 Wrangler default profile；device authorization 不会伪装成 named profile；
- 每个登录动作都绑定同一 Agent task 与冻结的 plan digest，强制按顺序执行，关闭认证命令的 Wrangler 磁盘日志，并且不返回 OAuth 原始输出；
- Cloudflare 登录与后续部署计划保持分离：登录本身不会创建 Worker 或 D1；
- 继续接受 Node.js `>=22.12.0 <27`，Wrangler 固定为 `4.127.1`。

重要限制：

- 这不是稳定发行通道，必须由用户明确选择；
- Wrangler named profiles 目前仍属于实验性能力；
- 请使用非生产 Cloudflare 账户，并分别核对准确的认证计划与部署计划后再授权；
- 资源清理是独立操作，绝不会自动执行。

安装带 tag 的 plugin：

```text
codex plugin marketplace add https://github.com/breakstring/cfKanban.git --ref 0.1.0-alpha.4
codex plugin add cfkanban-agent-skills@cfkanban
```

新建 Codex 任务后只需要说：

```text
请使用 $cfkanban-deploy 为我部署一套 cfKanban。
```
