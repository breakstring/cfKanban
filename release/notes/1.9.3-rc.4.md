# cfKanban 1.9.3-rc.4

## 简体中文

相对 `1.9.3-rc.3`，本 RC 修正 Codex `@` 搜索入口的显示名，帮助用户识别编号和标题搜索。

- 通过标准 MCP 显示标题提供 `cfkanban-search`，修正上一版仍回退到 `cfkanban-mcp` 的原因。
- 保留搜索用途说明及完整编号、部分编号和标题关键词查询，无需重新连接 cfKanban 身份。
- 本地持久缓存和后台同步继续沿用 RC3；仅为显示名修复更新插件即可。

## English

Compared with `1.9.3-rc.3`, this RC corrects the Codex `@` search entry's display name, making identifier and title search easier to recognize.

- Supplies `cfkanban-search` through the standard MCP display title, correcting the previous fallback to `cfkanban-mcp`.
- Retains the search description and complete-identifier, number-prefix, and title-keyword queries without requiring a new cfKanban identity connection.
- Reuses RC3's persistent local cache and background synchronization; this display-name fix requires only a plugin update.

## 升级与已知限制 / Upgrade and known limitations

明确更新插件到 `1.9.3-rc.4` 并重新连接 MCP 或退出重开 Codex，以读取新的显示标题。相对 RC3 无新增 migration，schema 保持 **20**，API 保持 **0.1.0**；已运行 RC3 的 Service 无需为此修复升级，执行其他服务升级时仍须核对真实 ledger/schema。

Explicitly update the plugin to `1.9.3-rc.4` and reconnect MCP or quit and reopen Codex to read the new display title. There are no new migrations relative to RC3; schema remains **20** and API remains **0.1.0**. A Service already running RC3 does not need an upgrade for this fix; other Service upgrades still require actual ledger/schema checks.

本地协议测试和已安装 Codex 显示函数的隔离验证已通过，另一台电脑的实际 `@` 菜单仍待更新后验收。RC3 的首次同步、权限补齐及搜索范围限制继续适用，详见 [RC3 发行说明](https://github.com/breakstring/cfKanban/releases/tag/1.9.3-rc.3)。

Local protocol tests and an isolated check of the installed Codex display function have passed; the actual `@` menu on the test computer still needs acceptance after updating. RC3's initial-sync, permission-backfill, and search-scope limitations still apply; see the [RC3 release notes](https://github.com/breakstring/cfKanban/releases/tag/1.9.3-rc.3).
