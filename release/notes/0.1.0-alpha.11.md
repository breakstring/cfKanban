# cfKanban 0.1.0-alpha.11

Testing prerelease / 测试发行版

## English

This testing prerelease closes the Owner-bootstrap and deployment-receipt gap found after the first real Worker deployment reached a healthy `workers.dev` origin.

Changes:

- prepares the first Owner Credential only through the exact authorized task, operation, plan digest, Principal ID, and Credential ID;
- rechecks the frozen Wrangler config, complete migration ledger/schema readback, successful Worker deployment, exact origin, and pending Credential before generating bootstrap SQL;
- journals the private bootstrap SQL path and digest and rejects blind execution after any prior bootstrap attempt;
- verifies health, public discovery, authenticated `/api/v1/meta`, and `/api/v1/me`, including exact Instance, origin, Service/schema versions, Owner flag, Principal ID, Credential ID, and fingerprint;
- promotes pending to current and writes an idempotent redacted deployment receipt only after every check matches;
- resumes an interrupted local finalization with the exact current Credential instead of generating a second secret;
- strengthens ordinary `/me` Credential promotion to require consistent Principal resource IDs, an explicit Owner flag, and the exact Credential ID/fingerprint;
- retains the simplified Wrangler identity order from alpha.10: environment auth, an explicitly supplied profile, directory/config context, then default; account remains pinned in private `wrangler.jsonc.account_id`.

The existing rehearsal can update only its local canonical Skill to this version and then continue the unchanged alpha.8 Service plan and journal. This does not upgrade the deployed Service bundle or create a new deployment plan.

Important limits:

- this is not the stable channel and must be selected explicitly;
- use a non-production Cloudflare account and review each exact local, authentication, and deployment plan before approval;
- resource cleanup is separate and is never performed automatically.

Install the tagged plugin:

```text
codex plugin marketplace add https://github.com/breakstring/cfKanban.git --ref 0.1.0-alpha.11
codex plugin add cfkanban-agent-skills@cfkanban
```

Start a new Codex task and say:

```text
Use $cfkanban-deploy to deploy cfKanban for me.
```

## 简体中文

这个测试发行版补齐了首次真实 Worker 部署到健康 `workers.dev` 地址后发现的 Owner bootstrap 与 deployment receipt 缺口。

变更：

- 首次 Owner Credential 只能通过准确的已授权 task、operation、plan digest、Principal ID 与 Credential ID 创建；
- 生成 bootstrap SQL 前重新核对 Frozen Wrangler config、完整 migration ledger/schema 读回、成功的 Worker 部署、准确 origin 与 pending Credential；
- 在 journal 固定私有 bootstrap SQL 的路径和 digest，已有任何 bootstrap 尝试后拒绝盲目重跑；
- 同时核对 health、公开 discovery、认证后的 `/api/v1/meta` 与 `/api/v1/me`，包括准确 Instance、origin、Service/schema versions、Owner flag、Principal ID、Credential ID 与 fingerprint；
- 只有全部匹配后才把 pending 提升为 current，并写入幂等的脱敏 deployment receipt；
- 本地最终化中断时复用准确 current Credential，不生成第二个 secret；
- 普通 `/me` Credential 提升也必须核对一致的 Principal resource IDs、显式 Owner flag 与准确 Credential ID/fingerprint；
- 保留 alpha.10 已简化的 Wrangler 身份顺序：环境认证、用户明确给出的 profile、目录/config context、default；account 继续固定在私有 `wrangler.jsonc.account_id`。

现有演练只需把本地 canonical Skill 更新到本版，即可继续未变化的 alpha.8 Service plan 与原 journal；这不会升级已部署的 Service bundle，也不会生成新部署计划。

重要限制：

- 这不是 stable channel，必须由用户明确选择；
- 请使用非生产 Cloudflare 账户，并分别核对准确的本地、认证与部署计划后再授权；
- 资源清理是独立操作，绝不会自动执行。

安装带 tag 的 plugin：

```text
codex plugin marketplace add https://github.com/breakstring/cfKanban.git --ref 0.1.0-alpha.11
codex plugin add cfkanban-agent-skills@cfkanban
```

新建 Codex 任务后只需要说：

```text
请使用 $cfkanban-deploy 为我部署一套 cfKanban。
```
