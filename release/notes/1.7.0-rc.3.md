# cfKanban 1.7.0-rc.3

## 简体中文

相对 `1.7.0-rc.2`，本 RC 改善负责人菜单的外观与交互，让看板和事项详情中的人员选择更紧凑、一致。

- **共享紧凑人员菜单**：看板卡片与事项详情使用同一负责人菜单，选择、更换或清除负责人时体验一致。
- **更容易识别与操作**：圆形姓名首字符帮助识别人员，选中项显示勾选标记，支持键盘和触屏操作。
- **看板布局更稳定**：人员加载、失败重试与加载更多入口收在菜单内，避免这些状态撑开卡片、引起看板跳动。

## English

Compared with `1.7.0-rc.2`, this RC improves the appearance and interaction of assignee menus, making people selection more compact and consistent across boards and issue details.

- **One compact people menu**: Board cards and issue details share the same assignee menu for a consistent experience when selecting, changing, or clearing an assignment.
- **Easier recognition and interaction**: Circular name initials identify people, checkmarks show the selected option, and the menu supports keyboard and touch interaction.
- **A steadier board layout**: People loading, retries, and load-more controls stay inside the menu, preventing these states from expanding cards and shifting the board.

## 升级与已知限制 / Upgrade and known limitations

从 `1.7.0-rc.2` 升级没有新增 migration，schema 保持 **18**，API 保持 **0.1.0**；仍须核对实际迁移记录与 schema。从正式版 `1.6.0` 升级仍需先应用 `0018_read_query_indexes.sql`，再部署 Worker；Worker 回滚不会回退 D1。普通安装仍推荐 stable，实例升级与 Skill 更新独立执行。

圆形标记使用姓名首字符，本版没有上传头像能力。候选仅表示读取时有资格，保存时仍由服务端复核；已有权限、并发与结果核实规则保持不变。

Upgrading from `1.7.0-rc.2` adds no migration: schema remains **18** and the API remains **0.1.0**. Verify the actual migration ledger and schema. Upgrades from stable `1.6.0` still require `0018_read_query_indexes.sql` before Worker deployment. Worker rollback does not roll back D1. Regular installations should use stable; instance upgrades and Skill updates are independent.

Circular badges use name initials; this release does not provide avatar uploads. Candidates are eligible at read time, and the server checks eligibility again when saving. Existing permission, concurrency, and result-verification rules remain unchanged.
