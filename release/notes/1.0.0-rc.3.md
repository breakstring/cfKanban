# cfKanban 1.0.0-rc.3

## English

The third 1.0 release candidate introduces instance-wide unique participant names, improves Agent assignment and Issue completion, and adds controlled recovery when all Owner Credentials are lost. It remains a prerelease for cross-system acceptance testing, not a stable release.

- Display names are trimmed and Unicode NFKC-normalized. Uniqueness uses a locale-independent Unicode lowercase key; display casing is preserved after normalization. Both the display name and its key must contain 1–128 Unicode code points.
- Names allow letters, combining marks, numbers, underscore, hyphen, and middle dot. Internal whitespace, invisible characters, emoji, and other symbols are rejected. Exact reserved names are `admin`, `administrator`, `owner`, `system`, `管理员`, `所有者`, and `系统`; there is no substring filtering or LLM decision.
- Add exact-name lookup for assignable Principals in a Project, returning the stable Principal ID. Results are limited to the Owner or an active writer in a Project the caller may access. Name conflicts do not disclose the occupying Principal. The Web profile provides bilingual rules and validation feedback.
- Upgrade schema 7 to schema 8 with a name key, unique index, and write guards. Migration replaces ordinary spaces in existing names with underscores, first rejecting reserved names, unsupported automatic backfills, and collisions. It never adds suffixes or merges identities. Principal IDs, Credentials, Grants, and assignments remain stable; actual name changes increment the profile version.
- Completion summaries become optional and Issues can be completed directly. Completion still atomically appends an immutable structured completion record, preserving reopen and repeat-completion history.
- Add controlled same-Principal Owner recovery and instance discovery to the deployment Skill. Inspection and recovery preserve observed legacy names rather than rejecting the identity because of the new naming rules.
- Improve task examples, Howto guidance, working-directory Project association, example Project naming, brand icons, and plugin resource packaging.
- Pin plugin metadata, installation/deployment/join guides, and the testing pointer to this immutable RC. API version remains 0.1.0; this release adds no Cloudflare resources or subscriptions and does not change existing Public Join policies.

Before upgrading, inspect existing names and record a D1 restore point. Apply the schema 8 migration from the verified Service bundle and read back its column, index, triggers, and schema version. This migration tightens the naming contract: older Service Principal writes are incompatible with schema 8, and rolling back only the Worker does not restore the old behavior. D1 restoration requires separate authorization.

Local Skill/plugin updates and deployed Service upgrades remain separate operations. Windows/WSL, additional browsers, physical-device Passkey, fresh installation, and interrupted-upgrade acceptance remain part of RC testing.

## 简体中文

第三个 1.0 候选版本，统一用户名称规则，改善 Agent 指派与完成 Issue 的体验，并补齐 Owner 凭据全失恢复能力。仍为跨系统验收用的预发行版，不替代 stable。

- 用户显示名称在部署实例内唯一。创建和改名时去除首尾空白、执行 Unicode NFKC 规范化，以不依赖 locale 的 Unicode 小写键判重；展示保留规范化后的大小写。名称和判重键均限定为 1–128 个 Unicode 码点。
- 名称允许各语言文字、组合标记、数字及 `_`、`-`、`·`，拒绝内部空白、不可见字符、Emoji 和其他符号。完整名称匹配的保留词为 `admin`、`administrator`、`owner`、`system`、`管理员`、`所有者`、`系统`，不做子串过滤或 LLM 判断。
- 新增按名称精确查询目标项目可分配用户的接口，返回稳定 Principal ID。只返回当前有权查看项目中的 Owner 或有效 writer，不增加授权，也不公开同名占用者的身份。Web 资料页面提供双语规则和输入反馈；重名返回明确机器错误。
- schema 从 7 升至 8，新增名称判重键、唯一索引和写入保护。旧数据迁移将普通空格替换为下划线；先检查保留词、不支持自动回填的字符与名称碰撞，发现问题即停止，不自动添加后缀或合并身份。Principal ID、Credential、Grants 和已有分配保持稳定；名称实际变化时递增资料版本。
- 完成说明改为可选，支持直接完成 Issue；完成动作仍原子写入不可变结构化完成记录，保留重开与再次完成的历史。
- 部署技能补齐 Owner 凭据全部丢失后的受控恢复与实例发现，恢复同一 Owner Principal；已存在的身份名称在检查与恢复时保持原样，避免旧名称阻断恢复流程。
- 改善 Howto 与操作技能的任务示例、工作目录项目关联引导，统一示例项目名称，优化品牌图标与插件资源打包。
- 插件、安装/部署/加入指南及当前测试指针统一固定为本次不可变 RC。API 版本保持 0.1.0，不新增 Cloudflare 资源或订阅，不修改现有 Public Join 策略。

升级前需检查旧名称并记录 D1 restore point，使用本次已验证的 Service bundle 执行 schema 8 迁移并读回列、索引、触发器与 schema 版本。此迁移收紧名称输入合同；旧 Service 的 Principal 写入不兼容 schema 8，不能仅回滚 Worker 就恢复旧行为，D1 恢复需要单独授权。

本地 Skill/plugin 更新与线上 Service 升级是两个独立操作。Windows/WSL、其他浏览器、实体设备 Passkey、全新安装和升级中断恢复仍属于 RC 验收范围。
