# cfKanban 0.1.0-alpha.10

Testing prerelease / 测试发行版

## English

This testing prerelease simplifies Wrangler profile/account selection and fixes the D1 transaction failure found while continuing the first deployment rehearsal.

Changes:

- reuses an exact profile/account already frozen in a journal or receipt before any discovery;
- otherwise lets Wrangler resolve environment authentication and the current private deployment/config context without running profile discovery;
- inspects one named profile only when the user explicitly supplies it; explicit `--profile` takes precedence over directory/default context unless an environment credential shadows it;
- continues to select the exact account from read-only results, verify D1 access, and pin it in private `wrangler.jsonc.account_id`;
- removes explicit SQL transaction statements from generated migration-ledger and Owner-bootstrap files because Wrangler's remote D1 file-ingestion path supplies the transaction boundary;
- journals bounded migration readback facts and adds a strict recovery assessment for the exact case where the same authorized journal proves a successful non-destructive migration but its checksum row is absent;
- refuses recovery for arbitrary existing schema, unknown ledger rows, other drift, destructive migrations, a different task/operation/plan/bundle, or a checksum write that reported success but is missing on readback;
- updates the Frozen Agent Skills contract, English/Simplified Chinese operational documents, plugin metadata, and tests.

The current rehearsal D1 already contains the complete initial application schema, while its cfKanban checksum row is absent because the earlier generated SQL was rejected before commit. No Worker or Owner Credential exists. After a separately authorized local Skill update, this release can re-read the same journal and D1, assess the narrow recovery preconditions, write only the missing insert-only checksum row, and then continue the unchanged original Service plan. A local Skill update does not upgrade the Service bundle or change the deployment plan.

Important limits:

- this is not the stable channel and must be selected explicitly;
- use a non-production Cloudflare account and review each exact local, authentication, and deployment plan before approval;
- resource cleanup is separate and is never performed automatically.

Install the tagged plugin:

```text
codex plugin marketplace add https://github.com/breakstring/cfKanban.git --ref 0.1.0-alpha.10
codex plugin add cfkanban-agent-skills@cfkanban
```

Start a new Codex task and say:

```text
Use $cfkanban-deploy to deploy cfKanban for me.
```

## 简体中文

这个测试发行版进一步简化 Wrangler profile/account 选择，并修复首次部署演练续做时发现的 D1 事务失败。

变更：

- 任何发现前先复用 journal 或 receipt 中已固定的准确 profile/account；
- 其他情况让 Wrangler 使用环境认证或解析当前私有部署/config 上下文，不再运行 profile discovery；
- 只有用户明确给出 named profile 时才检查那一个；除非被环境 Credential 遮蔽，显式 `--profile` 优先于目录/default 上下文；
- 继续从只读结果中选择准确 account、验证 D1 access，并将其固定到私有 `wrangler.jsonc.account_id`；
- 从生成的 migration-ledger 与 Owner-bootstrap 文件中移除显式 SQL 事务语句，因为 Wrangler 远端 D1 file ingestion 自己提供事务边界；
- 把有界 migration readback facts 记入 journal，并只为一种准确情形增加严格恢复判断：同一已授权 journal 已证明非破坏性 migration 成功，但 checksum row 缺失；
- 任意既有 schema、未知 ledger row、其他 drift、破坏性 migration、不同 task/operation/plan/bundle，或“checksum 写入显示成功但读回缺失”的矛盾，都会拒绝恢复；
- 同步更新 Frozen Agent Skills 合同、English/简体中文操作文档、plugin metadata 与测试。

当前演练 D1 已包含完整的初始应用 schema，但此前生成的 SQL 在提交前被拒绝，因此 cfKanban checksum row 仍缺失；Worker 与 Owner Credential 都尚未创建。本地 Skill 更新单独获得授权后，本版可以重新读回同一个 journal 与 D1，核对严格恢复前提，只补写缺失的 insert-only checksum row，然后继续原本未变化的 Service plan。本地 Skill 更新不会升级 Service bundle，也不会改变部署计划。

重要限制：

- 这不是稳定发行通道，必须由用户明确选择；
- 请使用非生产 Cloudflare 账户，并分别核对准确的本地、认证与部署计划后再授权；
- 资源清理是独立操作，绝不会自动执行。

