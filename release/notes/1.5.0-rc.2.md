# cfKanban 1.5.0-rc.2

## 简体中文

本次 RC 在 `1.5.0-rc.1` 基础上包含 CFK-531～535 的语言、看板更新、首页和首次加载改进。

- 全局语言入口统一使用通用翻译图标，提示和无障碍名称说明当前语言与切换目标；业务弹窗不再重复提供入口。切换语言保留未保存草稿，默认状态名称仍为英文，项目自定义状态名称和业务内容保留原文。
- 看板五列显示当前已提交筛选条件下、各状态未删除 Issue 的真实匹配总数，不再把已加载卡片数当作总数。计数与卡片列表分别处理加载、错误和显式重试，计数失败不会显示为零或阻塞已有卡片。
- 新建、状态移动、完成和优先级修改使用服务端确认的 Issue 局部更新卡片，保留已加载分页、可用 cursor、其他卡片与列滚动位置，并丢弃受影响的迟到分页响应。CAS 冲突和结果不确定时读回服务端事实；不自动覆盖草稿或重放业务写入。
- 公开首页恢复覆盖整个视口的连续暖色背景，修正页头、页脚的宽度、对齐、换行和窄屏触控布局；认证页面主题不再覆盖首页画布。
- 全部 11 个业务 View 按需加载，Nuxt UI provider 与认证页头只在认证路径加载。加载失败提供显式重试和用户触发的刷新，离页后忽略旧加载结果，刷新保留既有草稿保护。构建和 Service 打包校验 HTML、manifest、静态/动态引用与资源闭包，并强制入口 gzip ≤90,000 B、入口同步 JS 闭包 ≤95,000 B、最大 JS chunk ≤90,000 B 的预算。

本次没有新增 D1 migration；schema 保持 14，API 兼容版本保持 `0.1.0`，发行 manifest 保持 schema 2。没有新增云资源、付费要求或权限。Skills 更新与实例升级仍是独立操作，Worker 回滚不会回退 D1 schema。此 RC 不推进 main、stable 或 GitHub Latest。

性能数据来自本地生产产物与合成 API，未测量线上实例。相同冷缓存、150 ms 网络延迟、160 KiB/s 带宽与 CPU 4× 条件下，七个直接访问/首次导航场景各采样三次；采样在最终翻译图标微调之前完成。公开首页全部首屏 JS gzip 从 258,757 B 降至 92,563 B，可交互中位数从 2,463.9 ms 降至 1,513.0 ms。可交互终点使用页面就绪后的真实语言切换，不是标准 TTI。按需加载也使首次首页→看板和详情→管理分别增加约 988 ms、1,071 ms；所有 chunk 的 gzip 合计从 258,757 B 增至 290,195 B，不能据首屏减小声称全部体积或 CPU 成本下降。

最终图标微调后，首页与看板各补采一次：全部首屏 JS gzip 为 92,649 B / 193,435 B，可交互为 1,503.8 ms / 3,073.8 ms，全部 chunk gzip 合计为 290,291 B。这些是单次快速复核，不代替前述三次采样中位数，也不外推真实 API、D1 或线上网络性能。方法、原始数据和限制见[性能基线](https://github.com/breakstring/cfKanban/blob/1.5.0-rc.2/docs/research/2026-10-01-web-initial-load-performance.md)。

版本准备前的完整源码检查通过 588 项单元测试、149 项 D1 集成测试及 46 页双语文档检查。最终图标修订通过 122 项定向测试、typecheck 和构建；浏览器证据包含 36 项隔离 mock 回归，以及最终图标的 5 项定向 UI 检查。以上为已记录的开发验证，不代表本次 rc.2 候选或线上升级已通过验收。

本次 rc.2 候选的完整 `npm run validate` 已通过：588 项单元测试、149 项隔离本地 D1 集成测试、合同与 CI 一致性检查、Web/Worker 构建和 46 页双语文档检查。准确 rc.2 构建的入口、同步 JS 闭包和最大 chunk gzip 均为 85,876 B，预算校验通过。固定发行工件与线上升级读回由 [CFK-536](https://cfkanban.dev/app/issues/CFK-536) 记录；上述性能和浏览器数据仍属于本地验证，不代替线上验收。

## English

This RC builds on `1.5.0-rc.1` with the language, board update, homepage, and initial loading improvements from CFK-531–535.

- A universal translation icon provides the global language control, with a tooltip and accessible name describing the current language and switch target. Business dialogs no longer duplicate the control. Language changes preserve unsaved drafts; default status names stay in English, while custom project status names and business content keep their original text.
- All five board columns show the actual matching total of non-deleted Issues for the committed filters, rather than the number of cards loaded so far. Counts and card lists have independent loading, error, and explicit retry states. A count failure neither appears as zero nor blocks existing cards.
- Creation, status moves, completion, and priority changes update cards locally from the server-confirmed Issue, preserving loaded pages, usable cursors, other cards, and column scroll positions. Stale pagination responses for affected columns are discarded. CAS conflicts and uncertain outcomes trigger a readback of server facts, without automatically overwriting drafts or replaying writes.
- The public homepage restores a continuous warm background across the viewport and fixes header/footer width, alignment, wrapping, and narrow-screen touch layouts. Signed-in themes no longer override the homepage canvas.
- All 11 business Views load on demand, while the Nuxt UI provider and signed-in header load only on authenticated routes. Failed loads offer explicit retry and user-triggered refresh; departed pages ignore older load results, and refresh retains existing draft protection. Builds and Service packaging validate HTML, the manifest, static/dynamic references, and the asset closure. Gzip budgets enforce an entry ≤90,000 B, entry synchronous JS closure ≤95,000 B, and largest JS chunk ≤90,000 B.

No D1 migration is added. Schema remains 14, the API compatibility version remains `0.1.0`, and release manifests remain schema 2. No cloud resources, paid requirements, or permissions are added. Skills updates and instance upgrades remain separate operations; rolling back the Worker does not roll back the D1 schema. This RC does not advance main, stable, or GitHub Latest.

Performance figures use local production artifacts and synthetic APIs, without measuring the online instance. Each of seven direct-entry/first-navigation scenarios was sampled three times with cold caches, 150 ms network latency, 160 KiB/s bandwidth, and 4× CPU throttling, before the final translation icon adjustment. The public homepage's total initial JS gzip fell from 258,757 B to 92,563 B, and its median interaction endpoint fell from 2,463.9 ms to 1,513.0 ms. That endpoint uses a real language change after page readiness, rather than standard TTI. On-demand loading also adds about 988 ms to the first homepage→board navigation and 1,071 ms to the first details→management navigation. Summed gzip across all chunks rises from 258,757 B to 290,195 B; smaller initial loads do not establish lower total size or CPU cost.

After the final icon adjustment, one additional sample each for the homepage and board measured 92,649 B / 193,435 B of total initial JS gzip and interaction endpoints of 1,503.8 ms / 3,073.8 ms. Summed gzip across all chunks is 290,291 B. These are single quick checks, not replacement three-sample medians, and do not predict real API, D1, or online network performance. See the [performance baseline](https://github.com/breakstring/cfKanban/blob/1.5.0-rc.2/docs/research/2026-10-01-web-initial-load-performance.md) for methods, raw data, and limitations.

Before version preparation, complete source checks passed 588 unit tests, 149 D1 integration tests, and checks for 46 bilingual documentation pages. The final icon revision passed 122 focused tests, typecheck, and builds. Browser evidence includes 36 isolated mock regression checks and 5 focused UI checks for the final icon. These are recorded development checks, not acceptance of this rc.2 candidate or its online upgrade.

The complete rc.2 candidate `npm run validate` passed: 588 unit tests, 149 isolated local D1 integration tests, contract and CI consistency checks, Web/Worker builds, and checks for 46 bilingual documentation pages. The exact rc.2 build has 85,876 B gzip for its entry, synchronous JS closure, and largest chunk, passing all budgets. [CFK-536](https://cfkanban.dev/app/issues/CFK-536) records the pinned release artifacts and online upgrade readback. The performance and browser figures above remain local validation and do not establish online acceptance.
