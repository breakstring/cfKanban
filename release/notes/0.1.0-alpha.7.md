# cfKanban 0.1.0-alpha.7

Testing prerelease / 测试发行版

## English

This testing prerelease closes a Worker collision-safety gap found during the `0.1.0-alpha.6` deployment rehearsal. The D1 name had a bounded exact-name readback, but the Worker name did not; a new task could therefore describe the overall preflight as successful without proving that the planned Worker name was unused.

Changes:

- adds `runtime worker-resource-readback`, which returns only `present` or `absent` for one exact Worker name and never exposes deployment or account inventory;
- treats only Cloudflare machine error code `10007` as a missing Worker; every other non-zero or malformed response stops;
- requires both exact D1 and Worker readbacks before deployment authorization and again immediately before their corresponding writes;
- requires Worker presence plus the matching public `instance_id` marker after deployment before accepting ownership;
- disables Wrangler disk-log writes for read-only account, D1, and Worker probes;
- makes Cloudflare authentication profile identity independent of Skill or Service versions and requires reuse of a known profile/account pair that still passes readback;
- keeps the corrected D1 creation syntax and frozen account environment introduced in `0.1.0-alpha.6`.

The `0.1.0-alpha.6` rehearsal stopped before Owner planning and before any Cloudflare write. No Worker or D1 was created.

Important limits:

- this is not the stable channel and must be selected explicitly;
- use a non-production Cloudflare account and review each exact local, authentication, and deployment plan before approval;
- resource cleanup is separate and is never performed automatically.

Install the tagged plugin:

```text
codex plugin marketplace add https://github.com/breakstring/cfKanban.git --ref 0.1.0-alpha.7
codex plugin add cfkanban-agent-skills@cfkanban
```

Start a new Codex task and say:

```text
Use $cfkanban-deploy to deploy cfKanban for me.
```

## 简体中文

这个测试发行版修复了 `0.1.0-alpha.6` 部署演练发现的 Worker 同名安全缺口。D1 名称已有范围受控的准确读回，但 Worker 名称没有；因此新任务可能在尚未证明计划中的 Worker 名称无人使用时，就把整体预检描述为成功。

变更：

- 新增 `runtime worker-resource-readback`，只返回一个准确 Worker 名称的 `present` 或 `absent`，绝不暴露 deployment 或账户清单；
- 只有 Cloudflare 机器错误码 `10007` 才表示 Worker 不存在；其他非零结果或异常响应全部停止；
- 请求部署授权前，以及两个资源各自写入前，都必须执行准确的 D1 与 Worker 读回；
- Worker 部署后必须同时验证 Worker 存在和公开 `instance_id` marker 匹配，才能接受其所有权；
- 账户、D1 与 Worker 的只读探测统一关闭 Wrangler 磁盘日志写入；
- Cloudflare 认证 profile 身份不再与 Skill 或 Service 版本绑定；已知 profile/account 仍能通过读回时必须复用；
- 保留 `0.1.0-alpha.6` 引入的正确 D1 创建语法与冻结账户环境。

`0.1.0-alpha.6` 演练在 Owner 计划和任何 Cloudflare 写入前停止，没有创建 Worker 或 D1。

重要限制：

- 这不是稳定发行通道，必须由用户明确选择；
- 请使用非生产 Cloudflare 账户，并分别核对准确的本地、认证与部署计划后再授权；
- 资源清理是独立操作，绝不会自动执行。

安装带 tag 的 plugin：

```text
codex plugin marketplace add https://github.com/breakstring/cfKanban.git --ref 0.1.0-alpha.7
codex plugin add cfkanban-agent-skills@cfkanban
```

新建 Codex 任务后只需要说：

```text
请使用 $cfkanban-deploy 为我部署一套 cfKanban。
```
