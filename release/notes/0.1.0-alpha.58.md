# cfKanban 0.1.0-alpha.58

## English

This testing release includes alpha.57 usage statistics and Owner-selected attachment capacity, and fixes migration verification for the new capacity fields.

- Read back `attachment_storage` columns when reconciling schema 7. A regression test runs the actual published readback SQL and verifies every migration artifact.
- The updated deployment Skill can resume an alpha.57 upgrade interrupted after successful migration 7. It recognizes only the exact published alpha.57 bundle and readback digest, adds one fixed read-only column query in memory, and journals the source and executed SQL digests. Old release files, plans, and migrations are not modified.
- Missing migration checksums still require the same authorized journal, successful migration evidence, complete actual schema, and no other drift. Recovery does not repeat the migration or overwrite ledger rows.
- Web and Skill usage queries share the 15-minute successful cache and 60-second attempt cooldown. No statistics background polling is added. Cloudflare metrics require a separately authorized read-only Analytics Token.
- Attachment capacity remains an explicit Owner choice: a positive byte limit or unlimited. Upgrading the legacy fixed policy leaves it unconfigured and pauses new upload reservations until that choice; existing files and reservations remain intact.

This remains a prerelease. Upgrade from alpha.57 changes no database schema; interrupted upgrades must complete their existing journal before starting a new upgrade.

## 简体中文

本测试发行包含 alpha.57 的用量统计和 Owner 自主附件容量设置，并修复新容量字段的迁移验收。

- schema 7 读回补齐 `attachment_storage` 字段。回归测试执行实际发行读回 SQL，核对迁移清单中的全部 schema 产物。
- 新部署技能支持恢复在迁移 7 成功后中断的 alpha.57 升级：仅识别精确的 alpha.57 Service bundle 与旧读回脚本摘要，在内存追加一条固定只读字段查询，并记录原始/执行 SQL 摘要。不修改旧发行文件、计划或 migration。
- 补录 checksum 仍须同一已授权 journal、成功迁移证据、完整实际 schema 且无其他漂移，不重跑迁移、不覆盖 ledger。
- Web 和技能查询共用 15 分钟成功缓存与 60 秒尝试冷却，不增加统计后台轮询。Cloudflare 指标需要单独授权的只读统计 Token。
- 附件容量仍由 Owner 明确选择正整数字节上限或不限制；旧固定策略升级后为未设置，新预留暂缓，现有文件和预留保留。

此版本仍为 prerelease。从 alpha.57 升级不新增数据库迁移；中断升级先完成原 journal，再开始新升级。
