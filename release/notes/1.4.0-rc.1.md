# cfKanban 1.4.0-rc.1

## 简体中文

本候选版基于 `1.3.0`，新增站内双语文档中心，并补齐 Issue 结构化筛选与查询索引优化。

- 公开文档位于同实例 `/docs/`，按概述、使用、管理、部署组织，提供 English / 简体中文、目录、搜索、可复制 Agent 提示词及原始 Markdown。文档随 Service 静态打包并显示对应发行版本，不增加运行时服务或云资源。
- Web 看板和工作清单、Skills/API 支持按优先级和标签多选筛选；普通列表的负责人条件新增 `unassigned`。同维度多个条件按 OR、不同维度按 AND 组合，在服务端筛选后分页；更改条件须重新开始分页。
- 标签使用项目作用域的稳定 UUID，跨项目同名标签分别解析；只匹配可见项目内的有效标签，同一 Issue 命中多个标签不重复返回。候选队列支持优先级和标签，继续仅返回 `todo`，保留显式 `mine / unassigned / needs_reassignment` 策略。
- 根据查询条件选择状态、负责人、优先级或候选排序索引，并按项目和驱动条件取页后归并。标签查询复用反向关联索引。新增四个部分复合索引，保留旧索引和既有排序、权限与写入合同。
- daily Skill、howto 和中英文使用文档同步提供参数、标签解析、组合筛选与游标示例，并校验示例与 API 合同一致。
- 修复看板访问返回 403/404 后，标签被动清空导致访问错误提示消失的问题；成功重试后正常清除错误。

## English

This release candidate builds on `1.3.0`, adding an in-instance bilingual documentation center and structured Issue filters with query-index improvements.

- Public documentation lives at `/docs/` on the same instance, organized into overview, usage, administration and deployment. It provides English / Simplified Chinese, navigation, search, copyable Agent prompts and raw Markdown. Documentation is statically bundled with the Service and displays its release version, without adding runtime services or cloud resources.
- Web boards and work lists, Skills and API support multiple priority and label filters. Ordinary lists also accept `unassigned` as an assignee condition. Values within a dimension use OR; different dimensions use AND. Filtering runs on the server before pagination, and changed conditions require a fresh first page.
- Labels use stable, project-scoped UUIDs; identically named labels in different projects are resolved separately. Only active labels in visible projects match, and multiple matching labels do not duplicate an Issue. Candidate queues gain priority and label filters while retaining `todo`-only results and explicit `mine / unassigned / needs_reassignment` strategies.
- Queries select status, assignee, priority or candidate-order indexes according to their conditions, then merge pages from project and driving-condition branches. Label queries reuse the reverse relation index. Four partial composite indexes are added; existing indexes, ordering, authorization and write contracts are preserved.
- The daily Skill, howto and bilingual usage documentation include parameter, label-resolution, combined-filter and cursor examples, checked against the API contract.
- Board access errors from 403/404 responses now remain visible when selected labels are cleared indirectly, and clear after a successful retry.

## 升级与验证 / Upgrade and verification

从 `1.3.0` 升级时，先应用 `0013_issue_query_indexes.sql`，将 schema 从 `12` 升至 `13`，再部署本候选版 Worker。新版查询显式使用新增索引，不能跳过迁移。该迁移仅新增索引并更新 schema 版本，不改写业务行或已发行 migration；旧索引保留。API 仍为 `0.1.0`，实例、资源、身份、Credential、授权和业务数据保持原有语义。Worker 回滚不会回退 D1。

When upgrading from `1.3.0`, apply `0013_issue_query_indexes.sql` to advance schema `12` to `13` before deploying this candidate's Worker. New queries explicitly use the added indexes, so the migration cannot be skipped. It only adds indexes and updates the schema version, without rewriting business rows or released migrations; existing indexes remain. API stays at `0.1.0`, and existing instance resources, identities, credentials, grants and business data retain their semantics. Rolling back the Worker does not roll back D1.

索引优化存在存储和写入成本。隔离本地样本中，约 1.2 万条成本用例新增索引占用约 2.51 MiB；插入一个 `todo` Issue 的 D1 写入计数由 8 增至 12，同时更新负责人、优先级和更新时间由 5 增至 9。稀疏状态查询的单条结果 SQL 行读由旧查询形状的 646 降至 140，但密集标签仍随匹配关联数增长，其他条件交集也不保证固定页大小的读取成本。完整方法和边界见仓库 `docs/research/2026-09-29-issue-query-cost.md`；这些数字不是整次 HTTP 请求总消耗、线上计量或账单预测。

Index improvements have storage and write costs. In an isolated local fixture with approximately 12,000 cost-test Issues, the added indexes occupy about 2.51 MiB. D1's write count for inserting one `todo` Issue rises from 8 to 12; changing assignee, priority and update time together rises from 5 to 9. A sparse-status result SQL query drops from 646 rows read with the previous query shape to 140. Dense-label queries still scale with matching relations, and other filter intersections do not guarantee page-sized read costs. The method and limits are documented in `docs/research/2026-09-29-issue-query-cost.md`; these figures are not whole-request totals, live measurements or billing predictions.

已完成本地隔离的筛选、游标、权限和迁移回归，以及桌面与窄屏浏览器交互验证；浏览器验收使用模拟 API，数据库行为与计量另由隔离 D1 测试覆盖。访问错误修复已通过新增回归用例及相关 92 项测试、类型检查。发行提交的完整源码检查、工件校验与后续线上读回结果记录在发版 Issue，不将这些本地结果视为线上验收。Safari/Firefox 未验证。

Local isolated regressions cover filters, cursors, authorization and migration, with desktop and narrow-screen browser interaction checks. Browser checks use mocked APIs; isolated D1 tests separately cover database behavior and measurements. The access-error fix passes its new regression cases, 92 related tests and type checking. Full source checks, artifact verification and subsequent live readback for the release commit are recorded in the release Issue; local results do not establish live acceptance. Safari/Firefox were not tested.

新增筛选需要本候选版 Service/schema 13；本机 Skill/插件更新与实例升级独立执行，更新插件不能使旧实例支持新参数，也不证明当前 Codex 对话已重新加载。RC 不推进 GitHub Latest，canonical stable 继续指向 `1.3.0`。

The new filters require this Service release and schema 13. Local Skill/plugin updates and instance upgrades are separate operations: updating the plugin neither adds support to an older instance nor proves that the current Codex conversation has reloaded it. This prerelease does not advance GitHub Latest; canonical stable remains `1.3.0`.
