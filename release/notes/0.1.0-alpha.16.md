# cfKanban 0.1.0-alpha.16

Testing prerelease / 测试发行版

## English

This testing prerelease fixes local Credential promotion after live Invite redemption showed that the Service, correctly, assigns the Credential UUID while the older Skill also generated an unrelated local UUID.

Changes:

- records whether a pending Credential ID is `server_assigned` or exactly bound by a deployment plan;
- adopts the Credential ID authenticated by the same pending secret through `/api/v1/me` for Invite, Public Join, participant recovery, and Owner rotation;
- preserves strict UUID equality for deployment Owner bootstrap, where the ID is frozen in the authorized plan and bootstrap SQL;
- safely resumes legacy participant pending records while keeping legacy `owner_bootstrap` records exact-bound;
- keeps Principal binding, Credential fingerprint verification, private storage, and pending non-commit rules unchanged;
- adds regressions for Invite, Public Join, Owner rotation, legacy recovery, and exact Owner bootstrap mismatch rejection.

The correction changes only the Skill bundle and release documentation. An already deployed compatible Service does not need to be upgraded.

Important limits:

- this is not the stable channel and must be selected explicitly;
- use this version instead of alpha.15 for new/recovery Credential workflows;
- broader Web concurrency, target-scope, pagination, and browser hardening remain release-candidate work;
- host or operating-system permission prompts remain independent of cfKanban's application-level authorization.

Install the tagged plugin:

```text
codex plugin marketplace add https://github.com/breakstring/cfKanban.git --ref 0.1.0-alpha.16
codex plugin add cfkanban-agent-skills@cfkanban
```

Start a new Codex task and say:

```text
Use $cfkanban-admin to create my first cfKanban board.
```

## 简体中文

这次测试发行修复本地 Credential 提升：真实 Invite 兑换表明，Service 会按合同生成 Credential UUID，而旧 Skill 同时生成了一个无关的本地 UUID，导致成功兑换后无法从 pending 提升为 current。

变更：

- 明确记录 pending Credential ID 是由 `server_assigned`，还是由部署计划精确绑定；
- Invite、Public Join、参与者恢复和 Owner 轮换采用同一个 pending secret 经 `/api/v1/me` 认证得到的 Credential ID；
- 部署 Owner bootstrap 继续严格比较 UUID，因为该 ID 已冻结在获批计划与 bootstrap SQL 中；
- 可安全接续旧版参与者 pending，同时旧 `owner_bootstrap` 记录仍按精确绑定处理；
- Principal 绑定、Credential fingerprint 验证、私有存储与 pending 非提交证明规则保持不变；
- 新增 Invite、Public Join、Owner 轮换、旧 pending 恢复和 Owner bootstrap ID 不一致拒绝测试。

本次修正只改变 Skill bundle 与发行文档；已经部署的兼容 Service 无需升级。

重要限制：

- 这不是 stable channel，必须由用户明确选择；
- 新建或恢复 Credential 的流程应使用本版本取代 alpha.15；
- Web 并发、target scope、分页与浏览器加固仍属于 release candidate 工作；
- Agent 宿主或操作系统自己的权限提示仍独立于 cfKanban 应用层授权。

安装带 tag 的 plugin：

```text
codex plugin marketplace add https://github.com/breakstring/cfKanban.git --ref 0.1.0-alpha.16
codex plugin add cfkanban-agent-skills@cfkanban
```

新建 Codex 任务后只需要说：

```text
请使用 $cfkanban-admin 创建我的第一个 cfKanban 看板。
```
