# cfKanban 1.2.0

## 简体中文

本正式版基于用户确认验收的 `1.2.0-rc.3`，业务实现保持一致，汇总 1.2 系列的 Owner 多设备与部署维护改进。

- 同一 Owner 可以在不同电脑上使用独立 Credential。新设备在私有本地目录生成 secret，已有 Owner 设备或 Owner 管理网页核对非秘密配对请求后批准，新设备验证后完成接入；无需复制长期凭据。
- 网页「成员与权限 → Owner 设备」提供设备列表、配对预览、明确批准和专用撤销，正常 Owner 管理会话即可使用，无需额外 Passkey 确认。服务端保留同源、CSRF、实时权限、CAS、幂等及原子审计保护，禁止撤销当前认证来源和最后一份有效 Owner API Credential。
- 同实例已有本地身份的电脑可以明确切换为 Owner；新身份验证成功后才将旧身份保存到私有 previous 槽并切换 current。支持验证后的恢复和中断续做，不合并 Principal、不删除原授权。
- 新电脑可只读核验 Cloudflare 资源、实例、Owner 与 migration 状态后，接入已有部署用于后续维护。历史发行来源不明确时如实标记，不伪造工件证据；检查排除 Cloudflare/SQLite 内部表，避免无权读取内部表列信息。
- 服务端 active 凭据只表示未撤销，不证明本地 secret 文件仍在。有效 Owner 管理会话配合 active 记录可以批准新设备；专用部署外全失恢复继续撤销全部旧 API Credential，普通轮换继续使用 Agent 安全脚本。

## English

This stable release uses the user-accepted `1.2.0-rc.3` implementation without business changes and includes the 1.2 series improvements to Owner devices and deployment maintenance.

- One Owner can use independent credentials on multiple computers. A new device creates its secret in private local storage, an existing Owner device or Owner Web administration approves its public pairing request, and the new device verifies access. Long-lived credentials do not need to be copied.
- Owner Access provides device listing, pairing previews, explicit approval and dedicated revocation. A normal Owner admin session is sufficient without additional Passkey confirmation. Same-origin, CSRF, live authorization, CAS, idempotency and atomic audit checks remain enforced, and the current authentication source and last active Owner API Credential are protected.
- A computer with an existing local identity can explicitly switch to Owner. The new identity is verified before the old identity is retained in a private previous slot and current is switched. Verified restoration and interrupted-operation recovery preserve credentials without merging Principals or deleting grants.
- Another computer can attach an existing deployment for maintenance after read-only verification of Cloudflare resources, the instance, Owner and migration state. Unknown historical artifact provenance is recorded honestly. Inspection excludes Cloudflare/SQLite internal tables to avoid unauthorized internal-column queries.
- An active credential record proves only that it has not been revoked, not that its local secret file still exists. A valid Owner admin session with an active record can approve another device. Dedicated out-of-band recovery still revokes all old API Credentials, and normal rotation continues through Agent safety scripts.

## 升级与验收 / Upgrade and acceptance

从 `1.2.0-rc.3` 升级无新增 migration 或业务变更，schema 保持 `12`，API 保持 `0.1.0`。从 `1.1.1` 升级仅应用 `0012_owner_devices.sql`，增加可空 `credentials.device_name`；不重签发已有 Owner 或 Credential。新设备及身份切换功能需要支持它们的 Service 和 Skill，更新本地插件不会自动更新其他实例。

Upgrading from `1.2.0-rc.3` introduces no migration or business changes; schema remains `12` and API remains `0.1.0`. Upgrading from `1.1.1` applies only `0012_owner_devices.sql`, adding nullable `credentials.device_name` without reissuing existing Owners or credentials. Device and identity-switch features require supporting Service and Skill versions; a local plugin update does not upgrade other instances.

用户已确认 RC.3 验收完成并授权转正式版。自动化依据为 574 项隔离测试、桌面/手机浏览器组件检查，以及 RC.3 线上版本、资源和原凭据读回；用户验收确认与这些自动化证据分别记录，不把组件检查冒充所有真实跨电脑 E2E。正式版从准确提交重新构建工件，发布推进 GitHub Latest 与 canonical stable；线上部署和本机插件分别核验。更新磁盘上的插件不证明当前会话已重新加载。

The user confirmed RC.3 acceptance and authorized stable publication. Automated evidence includes 574 isolated tests, desktop/mobile browser component checks, and RC.3 live version, resource and unchanged-credential readback. User acceptance is recorded separately from automated evidence; component checks are not presented as all real cross-computer E2E flows. Stable artifacts are rebuilt from the exact release commit, publication advances GitHub Latest and canonical stable, and live deployment and local plugin installation are verified separately. Updating a plugin on disk does not prove the current conversation has reloaded it.
