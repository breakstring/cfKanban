# cfKanban 1.2.0-rc.1

## 简体中文

本候选版本支持 Owner 在多个可信 Agent 环境中使用独立凭据，并在新电脑上接入和维护已有 Cloudflare 部署。

- 新设备在本地私有存储中生成凭据，仅传递非秘密配对请求；已有 Owner 设备批准后，新设备核验实例、身份与准确 Credential，再提升为当前凭据。已有设备继续有效，可单独撤销另一设备。
- 新增已有部署的只读检查与本地接入回执，核对 Cloudflare 资源、D1 migration ledger/schema、实例和 Owner 身份，保留既有域名、R2 与用量配置。接入本身不写远端，也不伪造历史发行来源；无法证明原工件时，后续升级须明确接受该限制。
- 完善中断恢复：凭据已提升但残留 pending 元数据时，重新核验匹配的 current 后收尾；从未知工件来源升级时，将本次计划绑定的发布标识写入 Worker 版本，严格读回后可恢复响应丢失的发布，继续完成回执。
- 同步管理、部署和使用 Skills 的中英文操作说明。

## English

This release candidate lets the Owner use independent credentials across trusted Agent environments and attach an existing Cloudflare deployment for maintenance from a new computer.

- A new device creates its credential in private local storage and shares only a non-secret pairing request. An existing Owner device approves it; the new device verifies the instance, identity and exact credential before promotion. Existing devices remain active, and another device can be revoked individually.
- Read-only deployment inspection and a local attachment receipt verify Cloudflare resources, the D1 migration ledger and schema, instance identity and Owner access while preserving existing domains, R2 and usage configuration. Attachment makes no remote changes and does not invent historical release provenance. A later upgrade must explicitly accept any unverified prior artifact source.
- Interrupted operations can resume safely: credential promotion verifies a matching current credential before cleaning up residual pending metadata. Upgrades from an unverified artifact source bind a deployment marker to the approved plan and verify the remote Worker version before recovering a lost deployment response and completing the receipt.
- Updated bilingual administration, deployment and usage Skill guidance.

## 升级与验证边界 / Upgrade and verification boundaries

从 1.1.1 升级只新增 `0012_owner_devices.sql`：为 `credentials` 增加可空 `device_name`，schema 从 `11` 升至 `12`。迁移向后兼容且不删除数据；既有 Owner 和 Credential 不重签发。API 合同保持 `0.1.0`，产品版本与 API/schema 独立。升级仍须核对固定 migration manifest、ledger 和实际 schema，保留既有资源与配置；Worker 回滚不回退 D1。

Upgrading from 1.1.1 adds only `0012_owner_devices.sql`: a nullable `credentials.device_name` column and a schema change from `11` to `12`. The migration is backward compatible and does not delete data or reissue existing Owner credentials. The API contract remains `0.1.0`; product, API and schema versions remain independent. Upgrades still verify the pinned migration manifest, ledger and actual schema while preserving existing resources and configuration. A Worker rollback does not roll back D1.

本版本为预发行版，不推进 GitHub Latest 或 canonical stable。隔离验证不能替代真实跨设备、跨任务的宿主加载与功能验收；这些真实验收尚未完成。发行工件、线上部署和本机 Skill 安装分别读回，发布说明本身不证明线上已升级。更新磁盘上的 Skills 不会自动重载当前任务已加载的技能。

This is a prerelease and does not advance GitHub Latest or the canonical stable pointer. Isolated validation does not replace real cross-device and cross-task host loading and functional acceptance, which remain pending. Release artifacts, the deployed service and local Skill installation require separate readback; these notes do not establish that the live service has been upgraded. Updating Skills on disk does not reload those already loaded in the current task.
